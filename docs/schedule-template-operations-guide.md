# 근무표 양식 운영 가이드

## 목적

근무표 배포 양식이 변경되거나 수정이 필요할 때, 운영 중인 배포 흐름을 깨지 않고
버전별로 안전하게 관리하기 위한 절차를 정의한다.

## 기본 원칙

1. 운영 중인 양식 파일을 직접 덮어쓰지 않는다.
2. 양식 수정은 항상 `새 파일 + 새 버전`으로 등록한다.
3. 이미 저장된 월간 근무표는 저장 당시의 `templateVersionId`를 계속 사용한다.
4. 새 양식을 기본값으로 전환하기 전, preview/export 검증을 먼저 통과시킨다.
5. 구조가 달라지면 단순 버전업이 아니라 `새 양식 계열`로 취급한다.

## 현재 지원 양식

### 근무표 양식 1

- 파일: `근무표_템플릿1.xlsx`
- 계열: `sample1`
- 용도: Day / Evening / Night 일반형
- 적용 대상: 3교대 포함 일반 배포

### 근무표 양식 2

- 파일: `근무표_템플릿2.xlsx`
- 계열: `sample2`
- 용도: 6조 2교대형
- 적용 대상: Day / Night 전용
- 제약: `E` 근무가 있는 패턴에는 사용 불가

## 변경 요청이 들어오면 확인할 항목

1. 셀 주소가 바뀌는가
2. 상단 월/사이트/요약 위치가 바뀌는가
3. 좌측 메인 표의 주차 블록 수나 행 구조가 바뀌는가
4. 중앙 변경관리 표의 duty 컬럼 구성이 바뀌는가
5. 우측 대체근무/연장근무 영역의 드롭다운 구성이 바뀌는가
6. 기존 양식과 호환 가능한 수정인가, 새 양식 계열인가

## 운영 절차

### 1. 샘플 원본 보관

- 고객 또는 현업이 준 원본은 `양식샘플` 아래 샘플 파일로 보관한다.
- 원본 파일명은 수정하지 말고, 전달받은 기준 이름을 유지한다.

### 2. 운영용 템플릿 생성

- 샘플에서 실데이터를 제거한 운영용 템플릿을 별도 생성한다.
- 운영용 파일은 `_템플릿` 이름을 사용한다.
- 예:
  - `근무표_샘플1.xlsx` -> `근무표_템플릿1.xlsx`
  - `근무표_샘플2.xlsx` -> `근무표_템플릿2.xlsx`

### 3. 버전 등록

- 새 양식은 `document_template_versions`에 새 row로 추가한다.
- 기존 row는 수정하지 않고 남긴다.
- 버전 라벨은 사용자가 구분하기 쉽게 붙인다.
- 권장 예:
  - `근무표 양식 1`
  - `근무표 양식 1.1`
  - `근무표 양식 2`

### 4. 알고리즘 호환성 판단

- 기존 양식과 같은 셀 구조면 기존 계열(`sample1`, `sample2`)에 새 버전만 추가한다.
- 셀 구조가 달라지면 새 계열로 본다.
- 새 계열이면 아래를 같이 수정한다.
  - 템플릿 감지 로직
  - 좌측 메인 표 셀 배치
  - 중앙 변경관리 표 컬럼 매핑
  - 테스트

### 5. 검증

- 최소 검증 항목:
  - `inspectSchedulePlanTemplate`
  - `previewMonthlySchedulePlan`
  - `exportMonthlySchedulePlan`
  - `publishSchedulePlanExport`
  - `npm run typecheck`
- 배포 전 수동 확인:
  - 사이트명
  - 기준월
  - 팀 요약
  - 좌측 날짜/근무코드
  - 중앙 정규 계획
  - 변경 계획/사유 비움 상태

### 6. 기본 버전 전환

- 검증이 끝난 뒤에만 새 버전을 기본값으로 사용한다.
- 기본값은 `schedule` 템플릿 목록에서 최신 버전이 되도록 관리한다.
- 이미 저장된 월간 근무표는 예전 버전을 계속 참조하므로, 과거 export 재현성이 유지된다.

## 수정 유형별 처리 기준

### 단순 문구/색상/병합 조정

- 같은 계열 유지 가능
- 새 버전만 추가

### duty 종류 변경

- 새 계열 가능성 높음
- preview/export 알고리즘 수정 필요

### 주차 블록 수/행 구조 변경

- 새 계열로 처리
- 어댑터와 테스트 필수 수정

### 중앙 표 컬럼 변경

- 새 계열 또는 기존 계열 확장 여부 판단
- 정규 계획/변경 계획 컬럼 매핑 수정 필요

## 권장 운영 방식

1. 샘플 원본은 보관 전용
2. 운영 배포는 템플릿 전용 파일 사용
3. 버전은 추가만 하고 기존 것은 보존
4. 배포 화면에서는 사용자가 양식을 선택
5. 운영 관리에서는 어떤 양식이 기본 사용중인지 명확히 표시

## 추후 권장 기능

1. 운영 관리에서 템플릿 파일 직접 등록
2. 템플릿 버전 활성/비활성 관리
3. 템플릿 계열(`sample1`, `sample2`, 이후 신규 계열) 메타데이터 저장
4. 템플릿별 호환 패턴 표시
