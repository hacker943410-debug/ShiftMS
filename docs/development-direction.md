# 개발방향서

## 1. 프로젝트 정의

- 프로젝트명: ShiftMgmt_V3.4
- 제품 성격: 로컬 설치형 B2B 교대근무 운영 관리 시스템
- 목표: 파견지별 교대근무 운영, 월별 근무표 배포, 실적 승인, 수당 계산, 품의 문서 생성을 하나의 업무 흐름으로 통합한다.
- 배포 방식: Electron 기반 설치형 프로그램
- 운영 환경: 본사 내부 PC, 외부망 의존 최소화, 공휴일 데이터만 선택적으로 연동

## 2. 이 프로젝트가 해결해야 하는 문제

현재 업무는 엑셀 중심으로 분산되어 있으며 아래 문제가 반복된다.

1. 사이트별 근무 패턴과 조 편성이 달라 근무표 관리가 수작업에 의존한다.
2. 수정된 실적 파일 회수와 승인 과정이 분리되어 있어 이력 추적이 어렵다.
3. 대체근로, 연장근로, 야간근로, 법정휴일근로 계산이 수동 검산에 의존한다.
4. 월별 수당 산출과 품의 문서 작성이 마지막 단계에서 집중되어 운영 리스크가 커진다.

## 3. 제품 성공 기준

이 시스템은 보기 좋은 대시보드보다 먼저 아래를 정확하게 만족해야 한다.

1. 동일 입력에 대해 항상 동일한 근로시간과 수당 계산 결과를 낸다.
2. 승인된 실적은 원본 파일, 승인 시점, 적용 요율, 계산 결과를 다시 추적할 수 있다.
3. 사이트 패턴 변경, 인력 이동, 시급 변경 이력이 모두 남는다.
4. 월 마감 시 품의서와 별첨 자료를 다시 수기로 정리하지 않아도 된다.
5. 운영자는 시스템 안에서 월별 근무 현황과 수당 현황을 한 번에 검토할 수 있다.

## 4. 개발 방향

### 4.1 제품 방향

1. 이 프로젝트는 일반 사용자 대상 서비스가 아니라 본사 운영 조직을 위한 업무 시스템으로 설계한다.
2. 핵심 가치는 "자동화"보다 "정확성, 추적 가능성, 재현 가능성"에 둔다.
3. 초기 버전은 모바일보다 데스크톱 생산성과 데이터 밀도를 우선한다.
4. 엑셀은 폐기 대상이 아니라 외부 협업 채널로 간주하고, 시스템은 엑셀을 생성하고 회수하며 검증하는 허브 역할을 한다.

### 4.2 아키텍처 방향

1. `Electron main`은 파일 시스템, 폴더 감시, Excel 입출력, SQLite 접근을 담당한다.
2. `preload`는 renderer에 필요한 최소 기능만 안전하게 노출한다.
3. `renderer`는 화면 렌더링, 필터링, 사용자 상호작용만 담당한다.
4. 근무 패턴 계산, 근로시간 분해, 수당 산식, 승인 규칙은 `shared/domain` 성격의 순수 로직으로 분리한다.
5. 실적 승인과 수당 산출은 "입력 데이터 -> 계산 규칙 -> 결과 스냅샷" 구조로 저장한다.

### 4.3 도메인 우선순위

구현 우선순위는 아래 순서를 따른다.

1. 인증, 사용자 권한, 기본 앱 셸
2. 인력 관리, 근무지 관리, 패턴 시뮬레이션
3. 월별 근무표 생성과 Excel 양식 출력
4. 실적 파일 모니터링, 파싱, 승인/반려
5. 근로시간 계산과 수당 계산
6. 품의서/별첨 생성
7. 대시보드 시각화, 운영 관리 고도화

### 4.4 초기 범위와 제외 범위

초기 포함 범위:

1. 로컬 ID/PW 로그인
2. 사용자/관리자 권한 분리
3. 인력, 근무지, 패턴, 배정, 시급, 요율, 공휴일 관리
4. 근무표 Excel 생성
5. 승인대기/승인완료 폴더 모니터링
6. 실적 승인과 수당 계산
7. 품의서, 별첨1, 별첨2 생성

초기 제외 또는 후순위 범위:

1. 모바일 대응
2. 클라우드 멀티유저 동기화
3. 외부 메일 자동 발송
4. 복수 회사/복수 법인 멀티테넌시
5. AI 추천 기능

## 5. 핵심 도메인 컨텍스트

### 5.1 사용자 및 권한

- 관리자: 사용자 관리, 요율 관리, 공휴일 관리, 양식 관리, 시스템 설정
- 운영 사용자: 인력 관리, 근무지 관리, 근무표 배포, 실적 승인, 수당 확인, 품의 생성

### 5.2 핵심 엔터티

아래 엔터티를 중심으로 모델링한다.

1. 사용자
2. 인력
3. 근무지
4. 근무 패턴
5. 조 배정
6. 시급 이력
7. 월별 근무표
8. 실적 파일 원본
9. 실적 승인 이력
10. 공휴일
11. 수당 요율
12. 수당 계산 결과
13. 문서 양식 버전

### 5.3 비즈니스 핵심 규칙

1. 계산 규칙은 UI에서 조합하지 않고 도메인 서비스에서 일괄 적용한다.
2. 요율은 연도 기준 버전으로 관리한다.
3. 승인 시점의 원본 실적과 계산 결과는 변경 불가능한 기록으로 보존한다.
4. 재계산이 발생하더라도 승인 당시 계산값을 덮어쓰지 않고 새 버전으로 남긴다.
5. 근무지 삭제 시 배정 인력의 근무지/근무조는 자동 해제되지만 이력은 유지한다.

## 6. UI/UX 방향

이 프로젝트의 화면은 "기업형 운영 콘솔"이어야 한다. 예쁜 데모보다 업무 판단 속도와 신뢰감이 더 중요하다.

1. 기본 톤은 Corporate Blue Palette를 사용한다.
2. 레이아웃은 좌측 Sidebar Navigation + 우측 데이터 중심 메인 영역 구조를 유지한다.
3. 화면은 Ant Design 계열처럼 복잡한 데이터를 단정하고 예측 가능한 규칙으로 정렬해 보여준다.
4. 시각 장식은 절제하고, 카드/테이블/차트의 위계와 간격으로 정보 구조를 보여준다.
5. 수당, 근로시간, 승인 상태, 사이트별 비교가 첫 화면에서 바로 읽혀야 한다.

세부 UI 기준은 `docs/ui-design-brief.md`에 정의한다.

## 7. 기술 스택 방향

1. 앱 셸: Electron
2. UI: React + TypeScript + Vite
3. 로컬 데이터: SQLite
4. 파일 감시: Chokidar 계열
5. Excel 입출력: ExcelJS 계열
6. 라우팅: React Router 계열
7. 검증: Zod 계열
8. 테스트: Vitest + 도메인 계산 회귀 테스트
