# 패치내역 문구 작성 템플릿

## 목적
- 앱 내부 패치노트와 GitHub Release 본문을 운영자가 빠르게 이해할 수 있게 작성한다.
- `RELEASE_MANIFEST.json`의 `summary`에 모든 변경사항을 몰아넣지 않는다.

## 작성 원칙
1. `summary`는 2문장 이내, 220자 이하로 작성한다.
2. `summary`에는 “무엇이 좋아졌는지”만 적고, 테이블명/셀 주소/구현 세부사항은 섹션에 둔다.
3. `notes`는 5-8개 핵심 항목만 작성하고 번호를 직접 붙이지 않는다.
4. 상세 설명은 `sections[].items[]`에 업무 단위로 나눈다.
5. 한 문장에는 하나의 변경만 적는다.
6. 운영자가 확인해야 하는 값은 표로 분리한다.
7. “보정했습니다”, “정리했습니다”만 반복하지 말고 변경 전/후가 드러나게 쓴다.

## 표준 구조
```json
{
  "headline": "0.0.0 메뉴명 핵심 변경",
  "summary": "이번 업데이트는 [업무 영역]의 [문제/흐름]을 정리한 패치입니다. [핵심 결과]도 함께 반영했습니다.",
  "notes": [
    "운영자가 바로 체감하는 변경 1개",
    "운영자가 바로 체감하는 변경 1개"
  ],
  "sections": [
    {
      "title": "업무 영역",
      "description": "이 섹션에서 해결한 문제를 한 문장으로 설명합니다.",
      "items": [
        {
          "title": "변경 제목",
          "detail": "변경 전/후 또는 확인 기준을 1-2문장으로 설명합니다."
        }
      ]
    }
  ]
}
```

## 권장 섹션
- `화면/사용 흐름`: 메뉴 배치, 버튼, 검색, 필터, 모달 변경
- `데이터/복원`: DB 컬럼, Access/Excel 매핑, 기존 데이터 보정
- `문서 출력`: 품의서, 별첨, PDF, Excel 양식 변경
- `계산/정산`: 수당, 시급, 요율, 합계 계산 기준
- `검증/배포`: 테스트, 패키징, GitHub Release, smoke 결과

## 예시
```json
{
  "summary": "이번 업데이트는 인력관리 화면과 직원 정보 기준을 정리한 패치입니다. Access DB 직급 복원과 별첨1 출력 기준도 함께 보정했습니다.",
  "notes": [
    "인력관리 목록에 한 줄 필터와 하단 페이지게이트를 추가했습니다.",
    "직원 연락처와 직급을 저장하고 검색할 수 있게 했습니다.",
    "Access DB 실적 테이블의 직급명을 기준으로 직원 직급을 복원합니다."
  ]
}
```

## 금지 예시
- 여러 변경사항을 한 문단에 모두 이어 붙이지 않는다.
- `summary`에 셀 주소, 함수명, 파일 경로, DB 컬럼을 3개 이상 나열하지 않는다.
- `notes` 항목 앞에 `1.`, `2.` 번호를 직접 넣지 않는다.
