# 프로젝트 규칙

## 아키텍처
- renderer는 UI와 사용자 입력만 담당한다.
- 파일 시스템 접근, 폴더 감시, Excel 입출력, SQLite 저장은 main/preload를 통해서만 노출한다.
- 계산 규칙과 요율 계산은 `src/shared/domain` 또는 main 서비스에 둔다.

## UI
- 메뉴명, 버튼, 필터, 상태 라벨은 모두 한국어를 사용한다.
- 시각 스타일은 `ui-style-guide.md`를 기준으로 유지한다.
- 설계 원문에 없는 임의 메뉴 추가는 금지한다.

## 데이터 처리
- 승인 결과는 이력 기반으로 저장하고 조용한 덮어쓰기를 금지한다.
- 수당 계산은 승인 당시 저장한 실적 스냅샷만 기준으로 재현한다.
- 승인 또는 반려가 끝난 실적 파일은 다른 원본으로 같은 ID를 덮어쓸 수 없다.
- 승인 완료 시 원본 실적 파일은 승인 완료 폴더로 이동 보관하고, 보관 경로를 이력에 남긴다.
- 품의 신청은 동일 계산월의 수당 결과만 묶어서 품의서, 별첨1, 별첨2 파일과 출력 이력을 함께 남긴다.
- 직무 변경, 시급 변경, 승인 변경은 변경 시점이 남아야 한다.
- 공휴일과 요율은 연도 기준으로 관리한다.

## 개발 절차
- 3개 이상 파일을 동시에 바꿀 때는 변경 범위를 먼저 정리한다.
- 계산 규칙을 수정할 때는 문서와 테스트 기준을 먼저 맞춘다.
- 새 의존성 추가 전에는 Electron 빌드 리스크를 먼저 점검한다.

## 검증
- 최소 `npm run typecheck`, `npm run build`를 통과한다.
- 구조 변경 시 `node scripts/validate-structure.mjs` 검토를 추가한다.
