# 작업계획서

## 1. 추진 원칙

1. 화면보다 도메인 정확성을 먼저 확정한다.
2. 엑셀 입출력보다 먼저 내부 데이터 구조와 계산 규칙을 고정한다.
3. 모든 단계는 "샘플 데이터로 재현 가능"해야 다음 단계로 넘어간다.
4. 각 단계 종료 시 운영자가 직접 확인할 수 있는 데모 시나리오를 남긴다.

## 2. 단계별 계획

### Phase 0. 요구사항 고정 및 샘플 확보

- 목표: 실제 구현 기준이 되는 업무 규칙과 샘플 파일을 고정한다.
- 작업:
  1. 사용자 역할과 승인 책임 범위를 확정한다.
  2. 근무표 샘플, 실적 회신 샘플, 품의서/별첨 샘플을 수집한다.
  3. 근로시간 계산 예제를 최소 10건 이상 정의한다.
  4. 요율표와 공휴일 데이터 정책을 확정한다.
- 완료 기준:
  1. 샘플 파일 목록과 규격이 문서화되어 있다.
  2. 계산 예제와 기대 결과가 검증 데이터로 정리되어 있다.

### Phase 1. 앱 기반과 인증

- 목표: 설치형 앱 셸과 기본 보안 구조를 완성한다.
- 작업:
  1. Electron + React 앱 구조 고정
  2. 로컬 계정 로그인
  3. 사용자/관리자 권한 가드
  4. 공통 레이아웃, 사이드바, 기본 라우팅
- 완료 기준:
  1. 로그인 후 권한별 메뉴 접근이 분리된다.
  2. 메인/프리로드/렌더러 경계가 명확하다.

### Phase 2. 기준정보 관리

- 목표: 인력, 근무지, 패턴, 조 배정 등 기본 마스터 데이터를 관리할 수 있게 한다.
- 작업:
  1. 인력 관리 CRUD 및 이력
  2. 근무지 등록/수정/삭제
  3. 패턴 문자열과 조별 index 관리
  4. 근무지별 인력 배정
  5. 통상시급 및 상태 이력 관리
- 완료 기준:
  1. 한 사이트의 패턴과 조 편성을 시스템 안에서 재현할 수 있다.
  2. 인력 이동과 시급 변경 이력이 남는다.

### Phase 3. 패턴 시뮬레이션과 근무표 생성

- 목표: 월별 근무표를 계산하고 검토 가능한 상태로 만든다.
- 작업:
  1. 패턴 시뮬레이션 엔진 구현
  2. 월별 캘린더 뷰 구성
  3. 기본/연장/야간 예상 시간 계산
  4. 근무표 Excel 출력
- 완료 기준:
  1. 사이트별 월간 근무표가 UI와 Excel에서 동일하게 보인다.
  2. 샘플 패턴 기준 예상 시간 검증이 통과한다.

### Phase 4. 실적 수집과 승인

- 목표: 회신된 실적 파일을 자동 감지하고 승인 흐름으로 연결한다.
- 작업:
  1. 승인대기/승인완료 폴더 설정
  2. 파일 감시 및 중복 감지
  3. Excel 파서 구현
  4. 승인/반려 UI
  5. 승인 이력 저장
- 완료 기준:
  1. 지정 폴더에 파일이 들어오면 화면에서 식별된다.
  2. 승인/반려 후 상태와 이력이 저장된다.

### Phase 5. 근로시간 계산과 수당 엔진

- 목표: 승인된 실적을 기준으로 수당을 계산하고 재현 가능하게 저장한다.
- 작업:
  1. 휴게시간, 기본근로시간, 연장근로시간, 야간근로시간 계산 엔진
  2. 근로유형별 요율 적용 엔진
  3. 연도별 요율 관리
  4. 계산 결과 상세 테이블과 검산 화면
- 완료 기준:
  1. 문서의 예시 계산값과 테스트 결과가 일치한다.
  2. 승인된 실적 단위로 계산 근거를 추적할 수 있다.

### Phase 6. 대시보드와 운영 관리

- 목표: 운영자가 월별 현황을 빠르게 파악하고 운영 설정을 관리하도록 한다.
- 작업:
  1. KPI 카드와 차트 중심 대시보드
  2. 공휴일 관리
  3. 요율 관리
  4. 사용자 관리
  5. 양식 관리
- 완료 기준:
  1. 대시보드에서 근무시간/수당/근무지별 비교가 한 번에 보인다.
  2. 운영 설정 변경이 실제 계산/출력 흐름과 연결된다.

### Phase 7. 품의 산출과 릴리스 안정화

- 목표: 월 마감 산출물을 자동 생성하고 배포 가능한 수준으로 정리한다.
- 작업:
  1. 품의서, 별첨1, 별첨2 Excel 생성
  2. 오류 로그와 복구 시나리오 정리
  3. 설치 패키지 검증
  4. 사용자 테스트와 회귀 테스트
- 완료 기준:
  1. 월 마감 시나리오 전체가 한 번에 수행된다.
  2. 설치형 앱으로 재배포 가능한 상태가 된다.

## 3. 우선 개발 백로그

즉시 착수할 백로그는 아래 순서를 권장한다.

1. SQLite 스키마 초안
2. 도메인 타입 정의
3. 인증/권한 구조
4. 인력 관리 화면과 상태 이력
5. 근무지/패턴 등록 및 시뮬레이션
6. 계산 예제 기반 테스트 세트
7. 실적 파일 파싱 프로토타입

## 4. 병행 준비 항목

구현과 병행해서 준비해야 하는 비코드 항목이다.

1. 실제 Excel 양식 원본 정리
2. 샘플 실적 파일 익명화
3. 요율표 연도별 확정
4. 공휴일 데이터 소스 선정
5. 운영자 인터뷰로 예외 케이스 수집

## 5. 주요 리스크와 대응

1. 계산 규칙 해석 차이
   대응: 예제 데이터와 기대값 테스트를 먼저 고정한다.
2. 현장 회신 Excel 형식 불일치
   대응: 양식 버전 관리와 파서 호환 정책을 둔다.
3. 승인 후 재계산 분쟁
   대응: 승인 시점 계산 스냅샷과 적용 요율 버전을 함께 저장한다.
4. 로컬 파일 경로 의존성
   대응: 경로 설정, 권한 점검, 초기 진단 화면을 별도 제공한다.
5. UI 과복잡화
   대응: 첫 릴리스는 운영 핵심 플로우만 우선 구현하고 부가 시각화는 후순위로 둔다.

## 6. 각 단계의 산출물

각 Phase 종료 시 아래 산출물을 남긴다.

1. 구현 범위 요약
2. 테스트 결과
3. 남은 리스크
4. 운영 데모 시나리오
5. 문서 업데이트 내역
