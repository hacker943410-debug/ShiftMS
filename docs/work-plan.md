# 작업 계획

## 목적
- `디자인샘플소스/화면설계.md` 재정의안을 구현 기준으로 삼아 화면을 다시 맞춘다.
- 이번 단계는 최종 화면 컨펌을 받기 위한 UI 패치 중심이다.
- 실제 서비스 연결은 화면 컨펌 이후 시작한다.

## 1단계. 화면 구조 재배치
1. 대시보드를 `대시보드.jpg`의 KPI 8개 + 차트 4개 구조로 재배치
2. 인력관리 목록을 `인력관리.jpg`의 단일 테이블 화면으로 재배치
3. 인력상세페이지를 `인력상세페이지.png` 기준의 3열 구조로 분리 구현
4. 근무지 등록 1단계를 `근무지관리1단계.png` 기준으로 재배치
5. 근무지 등록 2단계를 `근무지등록 2단계.png` 기준으로 재배치
6. 근무표 배포를 `근무표 배포.jpg` 배치 + `근무표배포설정.png` 테마로 재배치
7. 실적관리를 `실적관리.png`의 표 중심 승인 화면으로 재배치
8. 수당관리를 `수당관리.png`의 좌측 분석 카드 + 우측 상세 테이블 구조로 재배치

## 2단계. 설계 원문 보강 반영
1. 근무지 등록 1단계에 조별 Index 입력란 동적 생성
2. 근무지 등록 1단계에 총근로시간, 총 법정휴일근로시간 KPI 추가
3. 근무지 등록 2단계에 미배정/타 근무지 인원 조회 필터 추가
4. 근무지 등록 2단계의 조 탭을 근무유형 기준으로 동적 활성
5. 인력상세페이지의 통상시급 포맷, 이력 스크롤, 수정 가능/불가 영역 분리

## 3단계. 화면 컨펌용 정리
1. 각 메뉴별 샘플 대비 차이점 점검
2. 간격, 테이블 헤더, 버튼 위치, 카드 높이 미세 조정
3. 사용자 확인용 dev 빌드 재실행

## 화면 컨펌 이후 착수할 작업
1. 더미 데이터를 실제 bridge 호출로 전환
2. 인력 목록과 상세 화면 라우팅 연결
3. 근무지 등록 1단계와 2단계 상태 공유
4. 드래그 앤 드롭과 필터 동작 연결
5. 근무표 배포 경로 선택 및 Excel 생성 연결
6. 실적 승인 액션과 계산 로직 연결
7. 수당 상세 확장행과 품의서 생성 연결

## 검증 기준
- 화면 구조가 샘플 이미지와 육안상 동일한 수준으로 맞아야 한다.
- 설계 원문에 명시된 핵심 입력/출력 정보가 누락되면 안 된다.
- 컨펌 전 단계에서는 타입체크와 빌드가 유지되어야 한다.
