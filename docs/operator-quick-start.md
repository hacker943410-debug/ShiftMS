# 운영자 빠른 시작 가이드

## 목적
교대근무관리시스템 V0.4.14는 교대근무 운영자가 인력 현황, 근무표 배포, 실적 승인, 수당 계산, 수당 승인, 품의 승인, 문서 출력을 하나의 로컬 앱에서 처리하도록 만든 Electron 데스크톱 앱이다.
- 0.4.14 설치본이 생성되면 설치 파일명과 실행 파일명은 `ShiftMgmt-Setup-0.4.14-x64.exe`, `ShiftMgmt.exe` 를 사용한다.
- 설치본은 앱 실행에 필요한 Electron/Node 런타임을 포함하므로 사용 PC에 Node.js 또는 npm을 별도로 설치하지 않아도 된다.

## 설치 및 실행
1. `ShiftMgmt-Setup-0.4.14-x64.exe` 를 실행해 프로그램을 설치한다.
2. 설치 중 Access DB `.accdb` 복원용 `ACE OLEDB`가 감지되지 않으면 경고가 표시될 수 있다. 이 경우에도 앱 설치와 JSON 복원은 계속 가능하다.
3. 설치가 끝나면 설치된 `ShiftMgmt.exe` 를 실행한다.
4. 앱에 로그인한다.
5. 신규 계정이면 비밀번호 변경 화면을 먼저 완료한 뒤 운영 화면으로 들어간다.

## 최초 사용 전 준비
1. `운영 관리 -> 경로 설정`에서 아래 경로를 저장한다.
   - 승인 대기 폴더
   - 승인 완료 폴더
   - 근무표 내보내기 폴더
   - 품의서 저장 폴더
   - 별첨1 저장 폴더
   - 별첨2 저장 폴더
   - DB 자동 백업 폴더
   - 백업 주기 / 백업 시간
   - 복원 파일 경로
     - 백업 JSON `.json` 또는 Access DB `.accdb`
2. Access DB `.accdb` 복원을 사용할 운영 PC라면 `운영 관리 -> DB업데이트` 미리보기에서 사전 점검 결과를 먼저 확인한다.
3. 사전 점검에서 `ACE OLEDB` 부족이 표시되면 `Microsoft 365 Access Runtime` 또는 호환 Office/Access 구성 후 다시 확인한다.
4. `공휴일 관리`, `요율 관리`, `사용자 관리`, `사이트 명 관리`, `양식 관리`가 현재 운영 기준과 맞는지 확인한다.
5. 릴리즈 직전 검수는 `docs/operations-manual-qa-checklist.md` 와 최신 릴리즈 문서 기준으로 별도 기록한다.

## 권한 분담 요약
- `관리자`: 경로 설정, 공휴일/요율/사용자/양식 관리, 활동 이력, DB업데이트.
- `계획 담당`: 인력/근무지 기준정보 정리, 교대 패턴 정리, 근무표 배포.
- `승인 담당`: 실적 승인/재승인, 수당 승인/반려, 품의 승인.
- `사용자`: 조회와 일반 화면 접근. 관리자 메뉴와 승인/배포 action은 보이지 않는다.
- 모든 계정은 앱을 다시 시작하면 다시 로그인해야 한다.

## 일상 운영 흐름

### 1. 인력 및 근무지 기준정보 정리
- `인력 관리`에서 인력 기본정보, 연락처, 직급, 근무지 배정, 시급 이력을 확인한다.
- `근무지 관리`에서 패턴, 조 배정, 정원 구성을 확인한다.
- 품의서에 사이트/근무지 구분이 필요하면 근무지 등록 시 `사이트 명`을 선택한다.

### 2. 근무표 배포
- `근무표 배포`에서 대상 월과 근무지를 선택한다.
- 승인된 근무표 양식을 선택해 배포한다.
- 배포 결과는 저장 경로와 이력에서 다시 확인한다.
- 실적 파일은 나중에 이 배포/저장된 월간 근무표와 매핑해 해석하므로, 실적 승인 전에 해당 월/근무지 근무표 배포를 먼저 완료한다.

### 3. 실적 승인
- `실적 관리`에서 승인대기 파일을 확인한다.
- 실적 파싱은 회수 파일만 단독으로 계산하지 않고, 배포 시 저장된 월간 근무표의 근무일/근무코드/시작·종료시각/휴게시간을 기준으로 법정휴일근무와 대체근무 시간을 복원한다.
- 해당 월/근무지의 저장 근무표가 없으면 법정휴일근무 또는 대체근무 행이 0시간 경고로 표시될 수 있으므로, 먼저 근무표 배포 이력을 확인한다.
- 최초 승인 완료 시 파일은 자동으로 승인 완료 폴더로 이동한다.
- 재승인이 필요하면 `수당 관리`의 `근무지 반려`로 승인 완료 파일을 승인 대기 폴더로 되돌린다.
- 승인완료 폴더에 해당 실적 파일이 없으면 확인 메시지에서 동의한 뒤 근무지 반려를 계속 진행할 수 있다.
- 재승인 대상은 `재승인 대기`, 재승인한 행은 `재승인 완료` 상태로 표시된다.
- 이미 `품의승인`된 행은 재승인 화면과 승인완료 목록에서 `변경불가`로 표시되며 다시 승인할 수 없다.
- 파일 전체를 최종 반영할 때는 `재승인 확정`을 사용하고, 현재 파일의 `변경 가능` 행이 모두 재승인 완료된 경우에만 확정할 수 있다.
- 승인 대기 목록은 승인 대기 폴더의 현재 파일 기준으로 다시 갱신된다.
- 재승인 비교에서 `임의 시급 적용`을 누르면 재승인 계산에만 적용할지, 현재 직원 시급정보까지 클릭 시점 기준일로 갱신할지 선택한다.

### 4. 수당 관리 및 문서 출력
- `수당 관리`에서는 승인 즉시 생성된 수당 결과를 `검토대기 / 승인 / 반려 / 품의승인` 상태로 관리한다.
- 근무지 단위 `근무지 승인 / 근무지 반려`와 행 단위 `승인`으로 수당 상태를 관리한다.
- `근무지 반려`는 이미 행 단위 `승인`된 수당까지 함께 `반려`로 전환한다.
- `근무지 반려`를 실행할 때는 반려 사유 입력이 필수이며, 입력한 사유는 승인 이력에 남는다.
- 행 단위 `반려`는 사용하지 않고, 실적 정정이 필요할 때는 `근무지 반려`로 실적 재승인 흐름을 다시 시작한다.
- `품의승인` 상태 수당이 포함된 근무지는 최종 마감 건이 섞인 상태이므로 `근무지 반려`를 실행할 수 없다.
- 퇴직자 선지급이 필요하면 대상 행에서 선지급 날짜를 등록한다.
- 품의서, 별첨1, 별첨2는 `승인` 상태 수당만 Excel/PDF로 출력할 수 있다.
- 수정 품의서 Excel 양식은 고객사명이 있으면 고객사와 근무지명을 분리 표기하고, 고객사명이 없으면 근무지명을 `B:D` 병합 행으로 표시한다.
- 근무지 수가 샘플 양식의 기존 행 수보다 많거나 적어도 일반 지급/선지급/푸터 위치는 자동으로 이동한다.
- 2026-04 기본 품의서 양식은 일반 지급, 퇴사자 조기 지급, 총 합계, 지급 요청일/세부내역 순서로 출력된다.
- 2026-04 기본 별첨1 양식은 최종 Excel에 `별첨1` 시트만 남기며, 퇴사자 조기 지급 대상이 없어도 `해당 없음` 행을 출력하고 숫자 영역 `H:S`는 Blank로 둔다.
- 별첨1 상세 표 D열은 승인/수당 스냅샷의 직급을 출력하며, 기존 데이터처럼 직급이 없으면 `-`로 표시한다.
- 별첨1 하단 안내는 새 샘플 `별첨1` 시트 `24:45`행의 `Sort`와 계산식 문구/서식을 그대로 사용하고, 실제 금액은 `시급 * 요율 * 시간` 원 단위 올림 기준으로 생성된다.
- 최종 마감 전에는 상단 `품의 승인` 버튼으로 승인 대상과 PDF 출력 기준 내용을 미리 확인한다.
- `품의 승인`을 누르면 문서 출력, 품의 승인 기록 저장, 자동 백업이 함께 실행된다.
- 품의 승인 중 DB 반영이 실패하면 출력 문서와 백업 파일은 남을 수 있으므로, 안내 모달을 확인한 뒤 출력 경로와 백업 폴더를 점검하고 다시 시도한다.
- 문서는 운영 관리에서 저장한 경로로 저장된다.
- 재승인 후 문서가 필요하면 최신 수당 결과 기준으로 다시 출력한다.

### 5. 운영 관리 유지보수
- `공휴일 관리`에서 저장 목록과 API 목록을 비교해 반영한다.
- `요율 관리`에서 연도별 요율 버전을 관리한다.
- 요율을 수정하거나 적용할 때는 변경 사유 입력이 필수이며, 이 사유는 `최근 요율 변경 이력`과 활동 이력에 함께 기록된다.
- 기존 요율 수정 시 `적용 시작일`은 오늘 이전으로 변경할 수 없고, 이미 시작된 요율은 시작일 자체를 바꿀 수 없다.
- `사용자 관리`에서 운영 계정을 생성, 수정, 삭제한다.
- `사이트 명 관리`에서 근무지 등록 1단계에 노출할 사이트 명 선택값을 등록하고, 사용 중인 항목은 삭제하지 않고 수정으로 관리한다.
- `양식 관리`에서는 양식을 등록할 때 먼저 구조 확인을 하고, 2단계 편집기에서 도식 미리보기와 속성 패널로 문서 영역을 조정한다.
- 필요하면 고급 모드에서 셀 기준, 열 너비, 행 높이를 추가 보정하고 `검증 출력` 후 저장한다.
- 저장된 양식은 `승인` 후 실제 배포/출력 후보가 되고, `기본 사용`으로 자동 선택 기준을 전환한다.
- `경로 설정`에서는 DB 자동 백업 경로, 주기, 시간을 함께 관리한다.
- DB 자동/수동 백업을 실행하면 같은 시점의 운영 DB가 JSON과 Excel `.xlsx` 파일로 함께 저장되고, Access 원본 경로가 확인되면 `.accdb` 사본도 함께 보관된다.
- 기준정보를 JSON 백업본 또는 Access DB 기준으로 되돌릴 때는 `운영 관리 -> 경로 설정`에서 복원 파일을 지정한 뒤 우측 상단 `DB업데이트`를 실행한다.
- `DB업데이트`를 누르면 먼저 현재 DB 현황과 업데이트 후 예상 현황을 비교하는 미리보기 모달이 열린다.
- Access DB `.accdb` 복원을 선택한 경우 미리보기 상단 사전 점검에서 현재 PC의 `ACE OLEDB` 사용 가능 여부를 먼저 확인한다.
- Access DB 복원 시 실제 Access 스키마 기준의 `사업조직별근무실적.직급명`만 `사원 / 대리 / 과장 / 차장 / 부장` 선택값으로 정규화되어 인력 기본정보와 승인/수당 스냅샷에 저장된다.
- 미리보기 모달에서 변경될 건수와 대상 파일을 다시 확인한 뒤 `승인`을 눌러 실제 교체를 실행한다.
- 실행이 끝나면 같은 모달에서 업데이트 결과와 최종 DB 상태를 다시 확인한다.
- Excel 파일은 운영자가 임의로 핸들링할 수 있는 원본이므로 DB업데이트 복원 입력으로 선택하지 않는다.

## 현재 운영 규칙
- Pool 근무자가 수행한 대체근무는 실적 기록에는 남지만 실적 관리 화면과 수당 산출에서는 제외한다.
- 수당 계산은 승인 시점의 저장 스냅샷만 기준으로 재현한다.
- 재승인 확정 시 엑셀 파일 자체를 수정하지 않고 DB의 최신 승인 이력을 기준으로 반영한다.

## 권장 일일 점검
- `대시보드`에서는 좌상단 `월별 수당 지급 추이`, 우상단 `근무지별 수당 현황`, 좌하단 `근무 유형별 상위 인원 (Top 10)`, 우하단 `전사 수당 유형 비율` 순서로 읽는다.
- `대시보드`에서 월 단위가 아닌 운영 기간을 확인할 때는 조회 방식을 `기간 직접 지정`으로 바꾸고 시작 월과 종료 월을 지정한 뒤 지표와 내보내기 결과를 확인한다.
- `실적 관리`에서 승인 대기 파일이 남아 있는지 확인한다.
- `수당 관리`에서 `검토대기` 수당과 `품의 승인`이 필요한 승인 건이 남아 있는지 확인한다.
- `품의 이력`에서 최근 품의 승인 기록과 자동 백업 경고 여부를 확인한다.
- `운영 관리 -> 경로 설정`이 바뀌지 않았는지 확인한다.
