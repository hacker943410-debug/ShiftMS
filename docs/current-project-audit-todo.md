# 현재 프로젝트 구조 점검 및 Todo List

작성일: 2026-03-11

이 문서는 `docs/work-plan.md`의 상위 단계 계획을 현재 코드베이스 상태에 맞춰 다시 해석한 실행용 점검 문서다.

## 1. 현재 프로젝트 구조 요약

### 루트 기준 주요 디렉터리

- `src/main`
  Electron main process 진입점만 존재한다.
- `src/preload`
  renderer로 버전 조회만 노출하는 최소 bridge만 존재한다.
- `src/renderer`
  단일 대시보드 시작 화면과 전역 스타일만 존재한다.
- `src/shared`
  `formatCurrency` 유틸과 테스트만 존재한다.
- `docs`
  개발방향, 작업계획, 프로젝트 규칙, UI 브리프, UI 스타일 가이드가 정리되어 있다.
- `scripts`
  구조 검증 스크립트만 존재한다.
- `양식샘플`
  근무표/품의서 관련 샘플 Excel 파일이 존재한다.

### 현재 구현 상태

1. Electron + React + TypeScript + Vite 기반 실행 셸은 구성되어 있다.
2. main/preload/renderer 분리는 되어 있고, 앱 상태 조회, 인증 골격, 계산 미리보기용 IPC 초안이 연결되어 있다.
3. renderer는 로그인 화면, 세션 확인, 권한 기반 앱 셸 골격까지 연결되어 있으나 실제 라우팅과 메뉴별 데이터 연결은 아직 없다.
4. shared에는 근로시간 계산과 수당 계산 스냅샷 서비스의 최소 뼈대가 들어가 있다.
5. SQLite, 인증, Excel 입출력, 파일 감시, 계산 엔진, 문서 생성은 아직 미구현이다.

## 2. 확인 결과

### 문서와 코드가 일치하는 부분

1. 설치형 앱 셸 방향은 현재 구조와 맞다.
2. renderer에서 Node API를 직접 쓰지 않는 구조는 지켜지고 있다.
3. 도메인 로직을 shared로 분리하겠다는 방향은 잡혀 있다.
4. UI가 한국어 라벨 중심이라는 규칙은 대체로 반영되어 있다.

### 문서와 코드가 어긋나는 부분

1. UI 가이드의 Corporate Blue 방향과 현재 화면의 베이지/청록 계열 스타일이 다르다.
2. 인증과 실적/계산 흐름은 시작되었고, 기준정보 CRUD와 월간 배정의 최소 저장/조회, 근무표 Excel 셀 미리보기까지는 실제 연결되었지만 배정 이력 편집, 시급 이력 관리 화면, 근무표 실제 파일 생성/배포 연동은 아직 미연결이다.
3. `shared/domain` 성격의 계산 모듈 구조가 아직 없다.
4. SQLite 저장소는 실적 파일 메타데이터, 실적 엔트리, 승인/계산 이력 중심의 최소 런타임 레이어만 연결되어 있고, 기준정보 CRUD와 정식 마이그레이션 체계는 아직 없다.
5. 샘플 Excel은 존재하지만 파서/생성기 어댑터 설계가 없다.

### 현재 기준선 상태

1. `npm run typecheck` 통과
2. `npm run test` 통과
3. `node scripts/validate-structure.mjs` 통과

현재 기준선은 "초기 셸은 정상"이지만 "업무 기능은 사실상 미구현" 상태로 보는 것이 정확하다.

## 3. 지금 해야 하는 작업

### 최우선 결론

가장 먼저 해야 할 일은 화면 확장이 아니라 아래 3가지를 고정하는 것이다.

1. 도메인 모델과 SQLite 스키마 초안
2. 계산 규칙 테스트 세트와 샘플 데이터 기준
3. Electron main 기준의 서비스 경계와 IPC 계약

이 3가지 없이 UI부터 확장하면 이후 Excel 파싱, 승인 이력, 수당 계산이 모두 다시 뜯어고쳐질 가능성이 높다.

## 5. 실제 착수 순서

현재 상태에서 바로 착수할 순서는 아래가 가장 안전하다.

1. SQLite 스키마 초안 문서 작성
2. shared 도메인 타입 정의
3. 계산 예제와 테스트 세트 작성
4. main/preload IPC 계약 설계
5. 로그인/권한/앱 셸 라우팅 구조 도입
6. 인력 관리, 근무지 관리 기본 CRUD 골격
7. Excel 파싱 및 파일 감시 프로토타입

## 6. 보류해도 되는 항목

초기 구현에서 바로 들어가지 않아도 되는 항목은 아래다.

1. 차트 고도화
2. 화려한 대시보드 시각화
3. 모바일 대응
4. 외부 메일 자동 발송
5. AI 추천 기능

## 7. 리스크 메모

1. 계산 규칙이 먼저 문서화되지 않으면 이후 모든 화면과 저장 구조가 흔들린다.
2. Excel 양식별 차이를 초기에 흡수하지 않으면 파서가 양식마다 깨질 가능성이 높다.
3. 승인 후 재계산 정책을 먼저 정하지 않으면 감사 추적 요구를 만족하기 어렵다.
4. renderer 중심으로 기능을 먼저 늘리면 Electron 경계 규칙을 깨뜨릴 위험이 크다.
5. 현재 UI 스타일은 문서 기준과 다르므로, 기능 개발 전에 디자인 토큰 정리가 필요하다.

## 9. 한 줄 평가
