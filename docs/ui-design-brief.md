# UI 디자인 브리프

## 1. 디자인 요청 원문

아래 문장을 이 프로젝트의 기본 UI 요청 프롬프트로 사용한다.

> B2B 교대근무 관리 시스템을 위한 Modern Admin Dashboard UI를 디자인해 줘. 화면 구조는 좌측에 Sidebar Navigation이 있고, 우측 메인 영역에는 수당과 근로시간을 보여주는 요약 카드와 Data Visualization(차트, 그래프)이 배치되어야 해. 전체적인 색상 테마는 신뢰감을 주는 Corporate Blue Palette를 사용하고, Ant Design 스타일처럼 복잡한 데이터를 Clean and Minimalist하게 정돈해서 보여줘.

추가 시각 기준의 소스 오브 트루스는 `디자인샘플소스/디자인지시서.md`로 둔다.
세부 구현 규칙은 `docs/ui-style-guide.md`를 따른다.

## 2. 해석된 디자인 방향

이 요청은 단순히 "예쁜 관리자 화면"이 아니라, 아래 목적을 가진 운영 콘솔 디자인으로 해석한다.

1. 수당과 근로시간처럼 숫자 중심 정보를 빠르게 읽어야 한다.
2. 근무지별, 근로유형별, 월별 비교가 쉬워야 한다.
3. 많은 표와 필터가 들어와도 지저분해 보이지 않아야 한다.
4. 신뢰감 있는 톤이 필요하므로 금융/엔터프라이즈형 위계를 사용한다.
5. 전체 테마는 다크 중심이 아니라 밝고 정돈된 라이트 모드를 기본으로 한다.

## 3. 비주얼 시스템

### 3.1 스타일 키워드

- Professional Light Mode
- Trustworthy
- Corporate
- Data-Dense
- Clean
- Minimalist

### 3.2 색상 방향

`디자인지시서.md` 기준의 라이트 모드 Corporate Blue 팔레트를 사용한다.

| 역할 | 색상 |
| --- | --- |
| Primary Background | `#F8F9FB` |
| Surface | `#FFFFFF` |
| Sidebar Surface | `#FFFFFF` |
| Sidebar Active Fill | `#EBF0FF` |
| Primary Accent | `#3E56B6` |
| Text Primary | `#1D2F3A` |
| Text Secondary | `#555555` |
| Border | `#D1D9F0` |
| Success | `#059669` |
| Warning | `#D97706` |
| Danger | `#DC2626` |

보조 원칙:

1. 보라는 계열의 SaaS형 그라디언트를 쓰지 않는다.
2. 차트 색상은 블루 계열을 기본으로 두고 상태 강조만 녹색/주황/적색으로 제한한다.
3. 배경과 카드, 사이드바는 모두 라이트 서피스를 유지하고 활성 상태만 로얄 블루 계열로 강조한다.
4. 카드와 버튼은 기본 `8px` 라운딩을 사용한다.

### 3.3 타이포그래피 방향

기본 방향은 "한글 가독성 + 숫자 신뢰감 + 엔터프라이즈 라이트 모드" 조합이다.

1. 본문/테이블: `Pretendard`
2. KPI 숫자/차트 수치/보조 라틴 텍스트: `Inter` 우선 검토
3. 숫자는 tabular lining 지원 폰트 또는 동일 폭 감각이 좋은 스타일을 우선 사용한다.

## 4. 레이아웃 원칙

### 4.1 기본 구조

1. 좌측 고정 Sidebar Navigation
2. 우측 상단 Context Header
3. 그 아래 KPI Summary Cards
4. 그 아래 차트와 테이블이 섞인 분석 영역

### 4.2 권장 정보 구조

1. Header
   연도, 월, 근무지, 이름 필터와 현재 화면 제목
2. KPI Band
   대체근로시간, 연장근로시간, 야간근로시간, 총근로시간
   대체근로수당, 연장근로수당, 야간근로수당, 총근로수당
3. Primary Visualization Row
   월별 근로시간 추이
   근무지별 수당 비교
4. Secondary Visualization Row
   근로유형별 수당 구성
   승인 상태 또는 예외 건수
5. Detailed Table
   근무지/인력별 상세 데이터

### 4.3 간격과 밀도

1. 카드 내부 여백은 넉넉하게 두되, 행 높이는 과하게 크지 않게 유지한다.
2. 테이블은 정보 밀도를 수용하되, 컬럼 정렬과 그룹 배경으로 읽기 쉽게 만든다.
3. 차트는 2개 이상 병렬 배치할 때 높이와 범례 위치를 통일한다.

## 5. 차트 가이드

업무 성격상 아래 차트 구성을 우선한다.

1. 선형 차트
   월별 근로시간 또는 수당 추이 표시
2. 가로 막대 차트
   근무지별 수당 비교, 근무지별 승인대기 건수 비교
3. 누적 막대 차트
   기본/연장/야간 구성비 또는 수당 구성비 표시
4. 테이블 병행
   모든 차트는 원본 수치를 확인할 수 있는 테이블 또는 툴팁을 함께 제공한다.

주의:

1. 레이더 차트는 축이 많아지면 가독성이 떨어지므로 제한적으로만 사용한다.
2. 파이/도넛 차트는 비율 요약이 명확할 때만 사용한다.
3. 색상만으로 상태를 전달하지 않는다.

## 6. 컴포넌트 방향

1. Sidebar
   그룹형 메뉴, 현재 위치 강조, 펼침 상태 일관성 유지
   기본 배경은 화이트 또는 매우 옅은 블루 톤으로 유지
2. Summary Card
   제목, 핵심 수치, 전월 대비 또는 기준값, 보조 설명으로 구성
3. Filter Bar
   Select, Date Picker, Search Input의 높이와 폭 체계 통일
4. Data Table
   고정 헤더, 정렬, 필터, 상태 배지, 우측 액션 아이콘
   행 높이는 답답하지 않게 여유를 주되 과도하게 커지지 않게 유지
5. Modal/Drawer
   등록/수정 작업은 집중도를 위해 모달 또는 우측 드로어를 사용

## 7. 상호작용 규칙

1. hover는 그림자/배경/테두리 변화 위주로 처리하고 레이아웃이 움직이지 않게 한다.
2. 애니메이션은 150ms~300ms 범위의 opacity/transform 위주로 제한한다.
3. 로딩 상태는 skeleton 또는 progress indicator로 명확히 보여준다.
4. 키보드 포커스가 분명하게 보여야 한다.

## 8. 금지할 디자인

1. 보라색 위주의 트렌디 SaaS 스타일
2. 과한 네온 효과와 글래스모피즘 남용
3. 카드마다 다른 톤을 쓰는 무질서한 색상 체계
4. 장식용 3D 아이콘, 이모지 아이콘
5. 데이터 화면에서 의미 없는 대형 히어로 섹션

## 9. 구현 전 체크리스트

1. 첫 화면에서 KPI와 필터가 즉시 읽히는가
2. 수당/근로시간/승인상태가 동일한 시각 규칙으로 표현되는가
3. 차트 없이도 표만으로 업무가 가능한가
4. 차트가 표를 보조하는 역할로 동작하는가
5. 한국어 레이블이 줄바꿈 없이 안정적으로 보이는가
6. 1440px, 1280px, 1024px 환경에서 정보 구조가 무너지지 않는가
