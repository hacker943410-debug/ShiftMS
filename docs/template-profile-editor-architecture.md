# 양식 프로필 편집기 아키텍처

## 목표

- 운영 관리에서 양식 등록, 검증, 프로필 편집, 승인, 배포 활성화까지 한 흐름으로 관리한다.
- 근무표, 품의서, 별첨1, 별첨2를 같은 등록 절차로 통일한다.
- 승인된 양식만 실제 배포 메뉴에서 선택 가능하도록 제한한다.
- 새 양식이 들어와도 동일한 의미 구조 안에서는 개발 코드 수정 없이 좌표와 규칙만 조정할 수 있게 한다.

## 사용자 흐름

1. `운영 관리 -> 양식 관리`에서 `양식등록` 버튼을 누른다.
2. `양식등록 1단계`에서 파일을 Import 하고 1차 검증을 실행한다.
3. 1차 검증이 통과하면 `양식등록 2단계`로 이동한다.
4. 좌측에는 현재 인식된 타이틀/좌표/규칙을 보여주고, 우측에는 수정 가능한 선택 목록과 규칙 입력을 제공한다.
5. `미리보기`를 실행해 실제 출력 결과를 확인한다.
6. `저장`을 누르면 양식 관리 테이블에 `미승인` 상태로 등록된다.
7. 운영 담당자가 테이블에서 `승인`을 누르면 상태가 `승인`으로 바뀐다.
8. `승인` 상태의 양식만 각 배포 메뉴의 양식 선택 목록에 노출된다.
9. 테이블에서는 수정/삭제/미리보기/승인 상태 확인이 가능하다.
10. 근무표, 품의서, 별첨1, 별첨2 모두 같은 절차를 사용하되, 프로필 스키마는 양식 종류별로 다르게 가진다.

## 핵심 원칙

- 제목 셀만으로는 전체 배포 좌표를 표현할 수 없으므로 `타이틀 기반 매핑 + 반복 규칙 기반 매핑`을 함께 쓴다.
- 양식 원본 파일은 직접 덮어쓰지 않고 항상 새 버전으로 등록한다.
- 미리보기와 저장은 분리한다.
- 승인 전에는 배포 메뉴에서 절대 선택되지 않는다.
- renderer는 파일을 직접 읽지 않고, 모든 파일 선택/검증/미리보기/저장은 main/preload를 통해 처리한다.

`document_template_versions`

- `template_type`
- `version_label`
- `source_path`
- `checksum`
- `status`: `pending` | `approved`
- `profile_schema_version`
- `profile_json`
- `validation_json`
- `created_at`
- `updated_at`
- `approved_at`
- `deleted_at`

### 상태 의미

- `pending`
  - 등록 완료, 편집 가능, 배포 비활성
- `approved`
  - 검증 완료, 배포 활성

- `sheetName`
- `templateFamily`
- `supportedFeatures`
- `fieldMappings`
- `layoutRules`

### 근무표 양식

필수 좌표

- 현장명 셀
- 월 제목 셀

- 변경 사유 컬럼

필수 규칙

- 근무 코드별 슬롯 배치
- 지원 근무 코드

### 품의서/별첨1/별첨2

- 문서 헤더 셀
- 대상 월/근무지/합계 영역 좌표
- 상세 표 헤더 시작 좌표
- 반복 행 증가 규칙

## 서비스 경계

### 1. 양식 Import / 1차 검증 서비스

- 파일 존재 여부
- 지원 확장자 여부
- 워크시트 존재 여부
- 필수 헤더 후보 탐지
- 중복 체크섬 검사
- 다음 단계 진입 가능 여부 반환

### 2. 양식 프로필 검사 서비스

- 워크북의 비어있지 않은 셀을 스캔한다.
- 제목 후보를 `주소 + 표시값` 형태로 제공한다.
- 중복 타이틀이 있으면 주소까지 함께 보여준다.
- merged cell 은 master cell 기준으로 정규화한다.

### 3. 양식 프로필 저장 서비스

- 프로필 JSON 검증
- 상태 `pending` 저장
- 수정 시 `updated_at` 갱신

### 4. 양식 미리보기 서비스

- 현재 프로필과 샘플 입력을 사용해 출력 파일을 만든다.
- 사용자가 직접 경로를 지정할 수 있다.
- 저장 없이 미리보기만 실행해도 된다.

### 5. 양식 승인 서비스

- `pending -> approved` 전이
- 승인 시각 저장
- 같은 종류의 기본 사용 후보로 승격 가능

## UI 구성

### 양식 관리 테이블

컬럼

- 양식 종류
- 버전
- 상태
- 파일명
- 생성일
- 승인일
- 작업

작업 버튼

- 미리보기
- 수정
- 삭제
- 승인

### 양식등록 1단계

- 양식 종류 선택
- 파일 Import
- 1차 검증 결과
- 다음 단계 이동 가능 여부

### 양식등록 2단계

- 좌측: 현재 인식된 필드/좌표/규칙
- 우측: 수정 가능한 선택 목록/규칙 입력
- 하단: 미리보기, 저장

## 배포 연동 규칙

- `근무표 배포` 메뉴는 `template_type = schedule AND status = approved` 인 양식만 조회한다.
- `품의서`, `별첨1`, `별첨2` 출력도 같은 규칙을 쓴다.
- 과거에 저장된 산출물은 당시 사용한 `templateVersionId` 를 계속 유지한다.

## 구현 순서

### 1단계

- 양식 상태 모델 추가
- 승인된 양식만 배포 메뉴에서 노출
- 양식 관리 테이블에 상태 표시

### 2단계

- 양식 Import / 1차 검증 IPC 및 main 서비스 추가
- 미승인 등록 저장 계약 추가

### 3단계

- 양식 프로필 편집기 UI 추가
- 타이틀 후보 스캔과 좌표/규칙 편집 연결

### 4단계

- 미리보기 경로 직접 선택
- 승인/수정/삭제 액션 마감

### 5단계

- 품의서, 별첨1, 별첨2까지 같은 프로세스로 확장

## 비범위

- 완전히 새로운 의미 구조의 엑셀을 무제한으로 자동 지원하는 기능
- renderer 에서 직접 파일을 읽거나 쓰는 기능
- 승인된 과거 양식의 무이력 덮어쓰기
