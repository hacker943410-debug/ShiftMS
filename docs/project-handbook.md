# 프로젝트 기준서

## 문서 역할
- 이 문서는 제품 방향, 개발 규칙, UI 기준, 현재 실행 계획을 한 곳에서 관리하는 기본 문서다.
- 상세 릴리즈 상태는 최신 릴리즈 문서, 실제 검수 기록은 `docs/operations-manual-qa-checklist.md` 를 기준으로 본다.
- 버전별 변경 누적 기록은 `docs/patch-notes.md` 에 남긴다.

## 프로젝트 개요
- 제품명: `교대근무관리시스템 V0.3.1`
- 설명: 교대근무 현황, 근무표 배포, 실적 승인, 수당 계산, 문서 출력을 통합 관리하는 로컬 데스크톱 앱
- 기술 스택: Electron + React + TypeScript + Vite
- 로컬 저장: SQLite
- 현재 작업 브랜치 기준: `git branch --show-current`
- 대상 릴리즈 브랜치: `release/0.3.1`

## 제품 목표
1. 본사 운영자가 사이트별 교대근무 현황을 한 화면에서 확인한다.
2. 근무표 배포, 실적 승인, 수당 계산, 품의서 생성까지 한 흐름으로 연결한다.
3. 로컬 데스크톱 앱 특성에 맞게 파일 접근과 감시는 main/preload 에서만 처리한다.

## 현재 릴리즈 범위
- 대시보드
- 인력 관리
- 근무지 관리
- 근무표 배포
- 실적 관리
- 수당 관리
- 활동 이력
- 운영 관리

운영 관리 범위에는 아래 항목이 포함된다.
- 경로 설정
- 공휴일 관리
- 요율 관리
- 사용자 관리
- 사이트 명 관리
- 양식 관리
- `DB업데이트`

## 아키텍처 / 데이터 원칙
1. renderer 는 UI와 사용자 입력만 담당한다.
2. 파일 시스템 접근, 폴더 감시, Excel 입출력, SQLite 저장은 main/preload 를 통해서만 노출한다.
3. 계산 규칙과 요율 계산은 `src/shared/domain` 또는 main 서비스에 둔다.
4. 승인 결과는 이력 기반으로 저장하고 조용한 덮어쓰기를 금지한다.
5. 수당 계산은 승인 당시 저장한 실적 스냅샷만 기준으로 재현한다.
6. 승인 또는 반려가 끝난 실적 파일은 다른 원본으로 같은 ID 를 덮어쓸 수 없다.
7. 승인 완료 시 원본 실적 파일은 승인 완료 폴더로 이동 보관하고, 보관 경로를 이력에 남긴다.
8. 공휴일과 요율은 연도 기준으로 관리한다.

## UI 기준

### 화면 구조
- 좌측 고정 사이드바 + 우측 메인 콘텐츠 구조
- 상단에는 현재 메뉴 제목과 운영 컨텍스트를 표시
- 본문은 필터 카드, 요약 카드, 테이블, 차트, 액션 영역으로 구성

### 화면 원칙
- 대시보드: KPI 카드, 차트, 우선 확인 영역을 같이 둔다.
- 인력 관리: 목록과 상세/이력 영역을 동시에 제공한다.
- 근무지 관리: 1단계 패턴 등록, 2단계 조직 구성 흐름을 분리한다.
- 근무표 배포: 월간 캘린더, 배포 경로, 배포 버튼을 같은 화면에 둔다.
- 실적 관리: 승인대기 목록과 계산 규칙 안내를 같이 둔다.
- 수당 관리: 요약, 상세 테이블, 품의 신청 흐름을 한 화면에서 연결한다.
- 운영 관리: 공휴일, 요율, 사용자, 양식 관리의 같은 톤을 유지한다.

### 스타일 기준
- 기본 배경: `#F8F9FB`
- 카드 배경: `#FFFFFF`
- 액센트: `#3E56B6`
- 본문 텍스트: `#1D2F3A`
- 보조 텍스트: `#6C798F`
- 기본 서체: Pretendard
- 주요 버튼: 파란색 배경 + 흰색 텍스트
- 상태 표기: 색상만 쓰지 말고 배지 텍스트를 함께 사용

### 금지
- 다크 모드 우선 설계 금지
- 과한 장식용 애니메이션 금지
- 영어 메뉴명 노출 금지
- 설계 원문에 없는 임의 메뉴 추가 금지

## 개발 절차
1. 3개 이상 파일을 동시에 바꿀 때는 변경 범위를 먼저 정리한다.
2. 계산 규칙을 수정할 때는 문서와 테스트 기준을 먼저 맞춘다.
3. 새 의존성 추가 전에는 Electron 빌드 리스크를 먼저 점검한다.
4. UI 코드는 한국어 라벨을 사용하고, 코드 주석은 영어로 유지한다.
5. 승인 후 결과는 재현 가능해야 하며 조용한 덮어쓰기를 금지한다.

## 릴리즈 / 버전 관리
1. 기능 개발과 일상적인 패치는 기능 브랜치에서 진행한다.
2. 배포 준비가 시작되면 현재 작업 브랜치에서 별도 `release/<version>` 브랜치를 만든다.
3. 현재 릴리즈 마감 분기 대상은 `release/0.3.1` 이다.
4. 공식 Windows 배포 산출물은 NSIS 설치본이다.
5. 내부 최종 검수용 산출물은 `npm run package:dir` 로 생성한 unpacked 앱 폴더다.
6. 패키징부터 실행 smoke 까지 한 번에 확인할 때는 `npm run release:verify-package` 를 사용한다.
7. 릴리즈 브랜치 분기 전에는 최소 아래 명령을 다시 통과한다.
   - `npm run test`
   - `npm run typecheck`
   - `npm run build`
   - `npm run smoke:electron`
   - `npm run release:check`
   - `node scripts/validate-structure.mjs`
