# 운영 관리 실데이터 수동 QA 체크리스트

## 목적
- `release/0.4.2` 분기 전 마지막 수동 확인 항목을 한 문서에서 실행하고 기록한다.
- 자동 smoke로 확인하지 못하는 실제 운영 데이터, 운영 PC 권한 정책, 네트워크 경로, 실제 양식/요율/공휴일 기준을 검증한다.
- 결과는 최신 릴리즈 문서 마감 근거로 사용한다.

## 사용 방법
- 이 문서는 실제 수동 QA 실행용 문서다.
- 각 항목은 `통과 / 보완 필요 / 실패 / 해당 없음` 중 하나로 기록한다.
- `보완 필요` 또는 `실패`는 반드시 하단 이슈 로그에 재현 정보를 남긴다.
- 섹션별 점검이 끝나면 요약 표를 채우고 마지막에 전체 결론을 기록한다.

## 작성 순서
1. `실행 정보` 와 `실행 전 준비` 를 먼저 채운다.
2. 1번부터 6번까지 순서대로 점검한다.
3. 문제를 발견하면 즉시 `이슈 로그` 에 남긴다.
4. `섹션 결과 요약` 과 `최종 결론` 을 마지막에 채운다.
5. 결과 요약은 최신 릴리즈 문서에 반영한다.

## 판정 기준
| 값 | 의미 |
|---|---|
| 통과 | 현재 릴리즈 후보 그대로 sign-off 가능 |
| 보완 필요 | 릴리즈는 보류하거나 조건부 진행 가능, 후속 수정 필요 |
| 실패 | 현재 상태로는 릴리즈 진행 불가 |
| 해당 없음 | 현재 운영 범위에서 사용하지 않는 항목 |

## 1. 경로 설정 / DB업데이트

### 목적
- 앱 전역 경로 설정이 실제 운영 환경에서 저장, 재조회, 재사용되는지 확인한다.
- `DB업데이트` 가 안내 문구, 미리보기, 실제 교체 결과까지 의도대로 동작하는지 확인한다.

### 권장 실행 절차
1. `운영 관리 -> 경로 설정` 에서 6개 경로와 복원 파일 경로를 실제 운영 경로로 저장한다.
2. 앱을 완전히 종료한 뒤 다시 실행해 저장값이 유지되는지 확인한다.
3. `실적 관리`, `수당 관리`, `근무표 배포` 등에서 같은 경로가 재사용되는지 확인한다.
4. 네트워크 드라이브 또는 사내 공유 폴더 경로를 1개 이상 포함해 저장/재조회한다.
5. `DB업데이트` 미리보기 모달을 열어 현재 DB 현황, 변경 예정 건수, 대상 파일 안내를 확인한다.
6. JSON 백업 또는 Access `.accdb` 기준으로 `DB업데이트` 를 실행하고 경로 설정이 유지되는지 확인한다.
7. Excel 파일이 복원 파일로 선택되지 않는지 확인한다.

## 3. 요율 관리

### 목적
- 실제 사용중 버전, 상태 카드, 요율 매트릭스, 변경 이력이 운영 기준과 맞는지 확인한다.
- 저장된 요율이 수당 산출 기준으로 실제 연결되는지 확인한다.

### 권장 실행 절차
1. 운영 사용 연도로 연도 필터를 변경한다.
2. `사용중 / 초안 / 종료` 상태 카드 수치를 운영 기준과 대조한다.
3. 신규 요율 버전 1건을 추가하고 버전명, 적용기간, 상태, 매트릭스 값을 저장한다.
4. 저장한 버전을 수정해 일부 값만 변경되는지 확인하고, 변경 사유 입력이 필수인지 확인한다.
5. 종료 처리 후 이력 보존과 계산 제외 규칙을 확인한다.
6. 사용중 버전을 바꾼 뒤 실제 수당 산출에서 반영되는지 확인한다.

## 4. 사용자 관리

### 목적
- 운영 사용자 목록, 역할/상태, 입력 검증, 관리자 최소 유지 규칙이 의도대로 동작하는지 확인한다.
- 첫 로그인 비밀번호 변경 강제, runtime-only 세션 정책, 역할별 메뉴/버튼 노출이 실제 구현과 일치하는지 확인한다.

### 권장 실행 절차
1. 실제 운영 사용자 목록과 현재 화면 목록을 대조한다.
2. 신규 사용자 1건을 생성한다.
3. 중복 계정명과 잘못된 메일주소로 저장을 시도해 검증 메시지를 확인한다.
4. 사용자 상태를 `사용중 / 중지 / 대기` 로 변경한다.
5. 관리자 계정을 최소 1명 미만으로 만들려 할 때 차단되는지 확인한다.
6. 신규 `planner` 와 `reviewer` 계정으로 각각 첫 로그인 후 비밀번호 변경을 수행한다.
7. `planner` 로그인 상태에서 `근무표 배포` 버튼은 보이고, `실적 관리`의 승인 버튼은 보이지 않는지 확인한다.
8. `reviewer` 로그인 상태에서 `실적 관리`와 `수당 관리`의 승인 계열 버튼은 보이고, `근무표 배포` 버튼은 보이지 않는지 확인한다.
9. `operator` 로그인 상태에서 관리자 메뉴가 숨겨지고 승인/배포 권한 버튼이 노출되지 않는지 확인한다.
10. 앱을 완전히 재시작하면 모든 역할이 다시 로그인해야 하는지 확인한다.
11. 운영에서 쓰지 않는 계정을 삭제한다.

## 5. 양식 관리

### 목적
- 양식 종류별 묶음, 구조 확인, 도식 편집, 승인, 기본 사용 전환, 파일명 규칙, 수정/보존, 이력 흐름이 운영 기준과 맞는지 확인한다.

### 권장 실행 절차
1. `근무표 / 품의서 / 별첨1 / 별첨2` 묶음별 건수와 상태를 실제 운영 기준과 대조한다.
2. 미승인 양식 1건을 승인한다.
3. 승인된 양식 1건을 `기본 사용` 으로 전환한다.
4. 출력 파일명 규칙을 변경한 뒤 실제 출력 파일명 반영 여부를 확인한다.
5. 구조 확인 결과의 시트/문서 영역/후보 위치가 양식 의도와 맞는지 확인한다.
6. 2단계 편집기에서 도식 미리보기, 속성 패널, 고급 모드 셀 보정이 정상 동작하는지 확인한다.
7. 수정 후 검증 출력 파일에 변경 내용이 반영되는지 확인한다.
8. 삭제 불가 조건이 필요한 양식에서 삭제 시도가 차단되는지 확인한다.
9. 최근 이력 표를 실제 작업 순서와 대조한다.

## 6. 운영 연계 확인

### 목적
- 운영 관리에서 변경한 기준정보가 실제 근무표 배포, 수당 계산, 수당 승인, 품의 승인, 문서 출력, 자동 백업, 계정 정책에 이어지는지 확인한다.

### 권장 실행 절차
1. 공휴일 1건을 변경하거나 반영한 뒤 근무표 배포와 수당 계산 기준에 반영되는지 확인한다.
2. 사용중 요율을 바꾼 뒤 새 수당 산출에서 변경분이 반영되는지 확인한다.
3. 실제 승인 데이터를 기준으로 `수당 관리`에서 행 단위 승인, 근무지 단위 승인, `근무지 반려 사유 입력`을 각각 1건 이상 확인한다.
4. `품의승인` 상태 수당이 포함된 근무지는 `근무지 반려` 버튼이 비활성화되고, 직접 호출도 실패하는지 확인한다.
5. 승인된 수당만 `품의 승인` 미리보기에 포함되고, 최종 승인 시 PDF 출력과 JSON/Excel 자동 백업이 동시에 실행되는지 확인한다.
6. 기본 사용 양식을 바꾼 뒤 근무표 배포 또는 품의서 출력에서 새 양식이 선택되는지 확인한다.
7. 사용자 상태 변경 뒤 운영자 계정 사용 정책과 충돌이 없는지 확인한다.
