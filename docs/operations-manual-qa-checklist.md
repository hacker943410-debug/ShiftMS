# 운영 관리 실데이터 수동 QA 체크리스트

## 목적
- `release/0.1.0` 분기 전 마지막 수동 확인 항목을 한 문서에서 실행하고 기록한다.
- 자동 smoke로 확인하지 못하는 실제 운영 데이터, 운영 PC 권한 정책, 네트워크 경로, 실제 양식/요율/공휴일 기준을 검증한다.
- 결과는 최신 릴리즈 문서 마감 근거로 사용한다.

## 사용 방법
- 이 문서는 실제 수동 QA 실행용 문서다.
- 각 항목은 `통과 / 보완 필요 / 실패 / 해당 없음` 중 하나로 기록한다.
- `보완 필요` 또는 `실패`는 반드시 하단 이슈 로그에 재현 정보를 남긴다.
- 섹션별 점검이 끝나면 요약 표를 채우고 마지막에 전체 결론을 기록한다.

## 작성 순서
1. `실행 정보` 와 `실행 전 준비` 를 먼저 채운다.
2. 1번부터 6번까지 순서대로 점검한다.
3. 문제를 발견하면 즉시 `이슈 로그` 에 남긴다.
4. `섹션 결과 요약` 과 `최종 결론` 을 마지막에 채운다.
5. 결과 요약은 최신 릴리즈 문서에 반영한다.

## 판정 기준
| 값 | 의미 |
|---|---|
| 통과 | 현재 릴리즈 후보 그대로 sign-off 가능 |
| 보완 필요 | 릴리즈는 보류하거나 조건부 진행 가능, 후속 수정 필요 |
| 실패 | 현재 상태로는 릴리즈 진행 불가 |
| 해당 없음 | 현재 운영 범위에서 사용하지 않는 항목 |

## 현재 전제
- 2026-03-24 기준 자동 검증은 통과 상태다.
- 자동 검증 범위: `npm run test`, `npm run typecheck`, `npm run build`, `npm run smoke:electron`, `npm run release:check`, `npm run release:verify-package`, `node scripts/validate-structure.mjs`
- 이 문서는 자동 검증을 대체하지 않고, 실제 운영 데이터 기준 검증만 담당한다.

## 1. 경로 설정 / DB업데이트

### 목적
- 앱 전역 경로 설정이 실제 운영 환경에서 저장, 재조회, 재사용되는지 확인한다.
- `DB업데이트` 가 안내 문구, 미리보기, 실제 교체 결과까지 의도대로 동작하는지 확인한다.

### 권장 실행 절차
1. `운영 관리 -> 경로 설정` 에서 6개 경로와 마이그레이션 파일 경로를 실제 운영 경로로 저장한다.
2. 앱을 완전히 종료한 뒤 다시 실행해 저장값이 유지되는지 확인한다.
3. `실적 관리`, `수당 관리`, `근무표 배포` 등에서 같은 경로가 재사용되는지 확인한다.
4. 네트워크 드라이브 또는 사내 공유 폴더 경로를 1개 이상 포함해 저장/재조회한다.
5. `DB업데이트` 미리보기 모달을 열어 현재 DB 현황, 변경 예정 건수, 대상 파일 안내를 확인한다.
6. JSON 백업 기준으로 `DB업데이트` 를 실행하고 경로 설정이 유지되는지 확인한다.
7. Access `.accdb` 기준으로 `DB업데이트` 를 실행하고 기준정보 반영 상태를 확인한다.

### 체크 항목
| ID | 확인 항목 | 결과 | 메모 |
|---|---|---|---|
| 1-1 | 승인 대기, 승인 완료, 근무표, 품의서, 별첨1, 별첨2 경로가 실제 운영 경로로 저장된다. |  |  |
| 1-2 | 마이그레이션 파일 경로는 폴더가 아니라 Access `.accdb` 또는 JSON `.json` 파일을 직접 선택해 저장한다. |  |  |
| 1-3 | 앱 재실행 후에도 저장한 경로가 그대로 유지된다. |  |  |
| 1-4 | 실적 관리, 수당 관리, 근무표 배포에서 같은 경로를 다시 조회했을 때 일치한다. |  |  |
| 1-5 | 네트워크 드라이브 또는 사내 공유 폴더를 써도 저장과 재조회가 정상이다. |  |  |
| 1-6 | `DB업데이트` 실행 전 안내 문구가 DB 교체 성격과 데이터 초기화 범위를 정확히 설명한다. |  |  |

| 1-8 | JSON 기준 `DB업데이트` 후 지정한 백업 내용으로 DB가 교체되고, 현재 경로 설정은 유지된다. |  |  |

### 확인 메모
- Access 복원 기대 범위:
  - 공휴일 / 요율 / 근무지 / 인력 / 시급 / 패턴 / 배정 종료일

5. 동기화 배너 문구와 상단 요약 카드 수치를 다시 확인한다.

## 3. 요율 관리

### 목적
- 실제 사용중 버전, 상태 카드, 요율 매트릭스, 변경 이력이 운영 기준과 맞는지 확인한다.
- 저장된 요율이 수당 산출 기준으로 실제 연결되는지 확인한다.

### 권장 실행 절차
1. 운영 사용 연도로 연도 필터를 변경한다.
2. `사용중 / 초안 / 종료` 상태 카드 수치를 운영 기준과 대조한다.
3. 신규 요율 버전 1건을 추가하고 버전명, 적용기간, 상태, 매트릭스 값을 저장한다.
4. 저장한 버전을 수정해 일부 값만 변경되는지 확인한다.
5. 종료 처리 후 이력 보존과 계산 제외 규칙을 확인한다.
6. 사용중 버전을 바꾼 뒤 실제 수당 산출에서 반영되는지 확인한다.

|---|---|---|---|
| 3-1 | 조회 연도를 바꾸면 해당 연도 버전만 다시 보인다. |  |  |
| 3-2 | 상태 카드의 `사용중 / 초안 / 종료` 수치가 실제 버전 수와 맞다. |  |  |
| 3-3 | 대표 요율 카드가 실제 사용중 버전을 기준으로 보인다. |  |  |
| 3-4 | 신규 요율 추가 시 버전명, 적용기간, 상태, 매트릭스 값 저장이 된다. |  |  |
| 3-5 | 수정 시 기존 항목이 유지된 채 변경분만 반영된다. |  |  |
| 3-6 | 종료된 버전은 이력으로 남고 계산 기준에서 빠진다. |  |  |

5. 관리자 계정을 최소 1명 미만으로 만들려 할 때 차단되는지 확인한다.
6. 운영에서 쓰지 않는 계정을 삭제한다.

## 5. 양식 관리

### 목적
- 양식 종류별 묶음, 승인, 기본 사용 전환, 파일명 규칙, 수정/보존, 이력 흐름이 운영 기준과 맞는지 확인한다.

### 권장 실행 절차
1. `근무표 / 품의서 / 별첨1 / 별첨2` 묶음별 건수와 상태를 실제 운영 기준과 대조한다.
2. 미승인 양식 1건을 승인한다.
3. 승인된 양식 1건을 `기본 사용` 으로 전환한다.
4. 출력 파일명 규칙을 변경한 뒤 실제 출력 파일명 반영 여부를 확인한다.
5. 좌표/프로필/설명 값을 수정하고 기존 값 보존 여부를 확인한다.
6. 삭제 불가 조건이 필요한 양식에서 삭제 시도가 차단되는지 확인한다.

## 6. 운영 연계 확인

### 목적
- 운영 관리에서 변경한 기준정보가 실제 근무표 배포, 수당 계산, 문서 출력, 계정 정책에 이어지는지 확인한다.

### 권장 실행 절차
1. 공휴일 1건을 변경하거나 반영한 뒤 근무표 배포와 수당 계산 기준에 반영되는지 확인한다.
2. 사용중 요율을 바꾼 뒤 새 수당 산출에서 변경분이 반영되는지 확인한다.
3. 기본 사용 양식을 바꾼 뒤 근무표 배포 또는 품의서 출력에서 새 양식이 선택되는지 확인한다.
4. 사용자 상태 변경 뒤 운영자 계정 사용 정책과 충돌이 없는지 확인한다.
