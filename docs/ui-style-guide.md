# UI 스타일 가이드

## 1. 목적

이 문서는 `디자인샘플소스/디자인지시서.md`의 시각 콘셉트를 실제 구현 가능한 규칙으로 변환한 기준서다.

이 문서의 역할은 아래와 같다.

1. 디자이너/개발자/AI가 같은 시각 규칙을 사용하게 한다.
2. 화면마다 다른 톤이 섞이지 않도록 공통 토큰을 고정한다.
3. 데이터 중심 B2B 화면에서 카드, 테이블, 차트, 필터를 일관되게 만든다.

## 2. 소스 오브 트루스

UI 관련 문서는 아래 우선순위로 해석한다.

1. `디자인샘플소스/디자인지시서.md`
2. `docs/ui-style-guide.md`
3. `docs/ui-design-brief.md`
4. `디자인샘플소스/화면설계.md`

충돌 시 상위 문서를 우선한다.

## 3. 디자인 원칙

1. 라이트 모드 기반의 전문적인 운영 콘솔을 유지한다.
2. 신뢰감은 과장된 효과가 아니라 정렬, 간격, 대비, 위계로 만든다.
3. 차트는 시선 유도용 장식이 아니라 판단 도구여야 한다.
4. 가장 중요한 정보는 카드가 아니라 필터와 수치 비교 구조에서 드러나야 한다.
5. 동일한 의미는 동일한 색, 동일한 배지, 동일한 컴포넌트 규칙으로 표현한다.

## 4. 디자인 토큰

### 4.1 색상

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--color-bg-app` | `#F8F9FB` | 전체 앱 배경 |
| `--color-bg-surface` | `#FFFFFF` | 카드, 패널, 모달 |
| `--color-bg-subtle` | `#F3F6FC` | 필터 바, 테이블 헤더, 보조 배경 |
| `--color-sidebar-bg` | `#FFFFFF` | 좌측 사이드바 기본 배경 |
| `--color-sidebar-active` | `#EBF0FF` | 사이드바 활성 메뉴 배경 |
| `--color-primary` | `#3E56B6` | 주요 액션, 활성 포인트 |
| `--color-primary-hover` | `#31479D` | 주요 버튼 hover |
| `--color-text-primary` | `#1D2F3A` | 본문, 제목 |
| `--color-text-secondary` | `#555555` | 보조 설명 |
| `--color-text-muted` | `#6B7280` | placeholder, 약한 메타 텍스트 |
| `--color-border` | `#D1D9F0` | 카드 경계, 입력 테두리 |
| `--color-success` | `#059669` | 성공, 승인 |
| `--color-warning` | `#D97706` | 주의, 대기 |
| `--color-danger` | `#DC2626` | 반려, 삭제, 위험 |
| `--color-info` | `#2563EB` | 정보성 상태, 공휴일 표시 |

색상 적용 규칙:

1. 기본 강조색은 `--color-primary` 하나를 중심축으로 사용한다.
2. 성공/경고/위험 색상은 상태와 배지에만 제한적으로 사용한다.
3. 표와 차트에서 동일 개념을 동시에 여러 색으로 표현하지 않는다.

### 4.2 타이포그래피

| 역할 | 폰트 | 크기 | 굵기 | 줄간격 |
| --- | --- | --- | --- | --- |
| 앱 기본 본문 | `Pretendard` | `14px` | `400` | `1.5` |
| 보조 본문 | `Pretendard` | `13px` | `400` | `1.5` |
| 필드 라벨 | `Pretendard` | `13px` | `500` | `1.4` |
| 테이블 셀 | `Pretendard` | `13px` | `400` | `1.4` |
| 페이지 제목 | `Pretendard` | `24px` | `700` | `1.3` |
| 섹션 제목 | `Pretendard` | `18px` | `600` | `1.35` |
| KPI 타이틀 | `Pretendard` | `13px` | `500` | `1.4` |
| KPI 수치 | `Inter` | `28px` | `700` | `1.2` |
| 차트 수치 | `Inter` | `12px` | `600` | `1.3` |
| 배지 텍스트 | `Pretendard` | `12px` | `600` | `1.2` |

타이포그래피 규칙:

1. 한글 UI는 `Pretendard`를 기본으로 한다.
2. 숫자, 금액, 시간, 증감률은 `Inter`를 우선 사용한다.
3. 제목은 크기로만 강조하지 말고 상하 여백과 섹션 분리로도 위계를 만든다.

### 4.3 간격

| 토큰 | 값 |
| --- | --- |
| `--space-4` | `4px` |
| `--space-8` | `8px` |
| `--space-12` | `12px` |
| `--space-16` | `16px` |
| `--space-20` | `20px` |
| `--space-24` | `24px` |
| `--space-32` | `32px` |

간격 규칙:

1. 카드 내부 기본 패딩은 `16px` 또는 `20px`를 사용한다.
2. 화면 섹션 간 간격은 기본 `24px`를 사용한다.
3. 관련성이 높은 컨트롤 묶음은 `8px` 또는 `12px` 간격으로 묶는다.

### 4.4 라운드와 그림자

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--radius-sm` | `6px` | 작은 배지, 작은 입력 |
| `--radius-md` | `8px` | 카드, 버튼, 입력 기본값 |
| `--radius-lg` | `12px` | 모달, 큰 패널 |
| `--shadow-sm` | `0 1px 2px rgba(29,47,58,0.04)` | 테이블/입력 |
| `--shadow-md` | `0 4px 12px rgba(29,47,58,0.06)` | 카드/모달 |

규칙:

1. 카드와 버튼의 기본 라운드는 `8px`다.
2. 그림자는 깊이 표현보다 레이어 분리를 위한 약한 수준만 사용한다.

### 4.5 선과 구분

1. 기본 보더는 `1px solid #D1D9F0`
2. 카드 내부 구분선은 배경색 대비가 과하지 않게 `#E7ECF7`
3. 테이블 row 구분은 너무 진하지 않게 유지한다.

### 4.6 모션

| 항목 | 값 |
| --- | --- |
| Hover transition | `180ms` |
| Panel/Modal | `220ms` |
| Page section reveal | `240ms` |

모션 규칙:

1. `transform`과 `opacity`만 사용한다.
2. `prefers-reduced-motion` 환경에서는 모션을 최소화한다.
3. 카드 hover 시 크기 확대는 쓰지 않는다.

### 4.7 브레이크포인트

| 토큰 | 값 |
| --- | --- |
| `--bp-desktop` | `1440px` |
| `--bp-laptop` | `1280px` |
| `--bp-tablet` | `1024px` |

프로젝트 기본 타깃은 데스크톱이다. 모바일 재배치는 초기 범위에 포함하지 않는다.

## 5. 레이아웃 기준

### 5.1 앱 셸

| 영역 | 권장값 |
| --- | --- |
| 좌측 사이드바 너비 | `248px` |
| 상단 헤더 높이 | `64px` |
| 메인 콘텐츠 최대 폭 | `1440px` |
| 페이지 좌우 패딩 | `24px` |
| 페이지 상하 패딩 | `24px` |

레이아웃 규칙:

1. 사이드바는 고정 영역으로 유지한다.
2. 헤더는 페이지 제목, 사용자 정보, 보조 액션을 담는다.
3. 메인 콘텐츠는 `필터 -> KPI -> 분석 -> 상세 테이블` 순으로 배치한다.

### 5.2 필터 바

1. 필터 바는 한 줄에서 읽히는 정렬이 우선이다.
2. 컨트롤 높이는 기본 `40px`를 사용한다.
3. 검색 입력은 React에서 `useDeferredValue` 또는 debounce를 적용한다.
4. 필터와 액션 버튼은 좌우 끝에 흩지 말고 논리 단위로 묶는다.

### 5.3 섹션 카드

1. 모든 분석 영역은 카드 단위로 묶는다.
2. 카드 헤더에는 제목, 보조 설명, 우측 액션을 배치한다.
3. 카드 안에 차트와 표가 함께 있을 때 시각 밀도 차이를 줄인다.

## 6. 컴포넌트 가이드

### 6.1 버튼

기본 유형:

1. Primary
   배경 `#3E56B6`, 텍스트 화이트
2. Secondary
   화이트 배경, 블루 보더, 블루 텍스트
3. Tertiary
   보더 없이 텍스트만 사용
4. Danger
   위험 액션 전용

규칙:

1. 버튼 높이는 기본 `40px`
2. 좌우 패딩은 `14px ~ 16px`
3. 아이콘 버튼은 `40x40px` 이상
4. 로딩 중에는 버튼 비활성화

### 6.2 입력, 셀렉트, 날짜 선택기

1. 기본 높이 `40px`
2. 라벨은 위쪽 정렬
3. placeholder는 보조 텍스트 톤
4. 오류 메시지는 필드 바로 아래에 표시하고 `role="alert"`를 사용한다.

### 6.3 배지

| 타입 | 배경 | 텍스트 |
| --- | --- | --- |
| 승인 | `#ECFDF5` | `#047857` |
| 승인대기 | `#FFF7ED` | `#C2410C` |
| 반려 | `#FEF2F2` | `#B91C1C` |
| 공휴일 | `#EFF6FF` | `#1D4ED8` |
| 연장근로 | `#FFF7ED` | `#C2410C` |
| 야간근로 | `#EEF2FF` | `#4338CA` |
| 대체근로 | `#EFF6FF` | `#1D4ED8` |

규칙:

1. 배지는 색상만이 아니라 텍스트를 반드시 포함한다.
2. 같은 의미의 배지는 모든 화면에서 같은 색을 사용한다.

### 6.4 KPI 카드

구성:

1. 제목
2. 현재 값
3. 보조 설명 또는 전월 대비
4. 단위

규칙:

1. KPI 카드는 한 줄에 4개 기준으로 배치한다.
2. 카드 높이는 동일하게 맞춘다.
3. 증감은 작은 보조 텍스트로 처리하고 주 수치를 흐리지 않는다.

### 6.5 데이터 테이블

기본 규칙:

1. 헤더는 sticky를 우선 검토한다.
2. 가로 폭이 넓으면 `overflow-x-auto` 래퍼를 사용한다.
3. 숫자 컬럼은 우측 정렬한다.
4. 날짜와 시간은 고정 폭을 준다.
5. 상태 컬럼은 배지 형태로 통일한다.
6. 행 높이는 답답하지 않게 `44px ~ 52px` 범위를 유지한다.

가독성 규칙:

1. Zebra striping은 매우 약하게만 사용한다.
2. 선택 행과 hover 행은 같은 방식으로 강조하지 않는다.
3. 액션 컬럼은 우측 고정 또는 마지막 열로 통일한다.

### 6.6 모달과 드로어

1. 신규 등록은 기본적으로 모달
2. 상세 수정과 이력 확인은 우측 드로어 또는 상세 페이지
3. 모달 최대 폭은 `640px`, 큰 설정형 모달은 `800px`
4. 저장/취소 버튼은 하단 우측 정렬

### 6.7 차트

권장 차트:

1. 선형 차트: 월별 추이
2. 가로 막대 차트: 근무지별 비교
3. 누적 막대 차트: 근로유형 구성비

규칙:

1. 파이/도넛 차트는 핵심 비교 화면에서 우선 사용하지 않는다.
2. 차트 색상 순서는 `Primary -> Info -> Success -> Warning -> Danger`
3. 모든 차트는 툴팁 또는 표로 원본 수치를 확인 가능해야 한다.
4. 범례는 상단 우측 또는 하단 고정 위치로 일관되게 둔다.

### 6.8 빈 상태, 로딩, 오류

1. 빈 상태는 "데이터 없음"만 쓰지 말고 다음 행동을 안내한다.
2. 로딩은 skeleton을 우선 사용한다.
3. 오류는 색상 + 텍스트 + 복구 버튼 조합으로 표시한다.

## 7. 접근성 기준

아래 항목은 필수다.

1. 일반 텍스트 대비 `4.5:1` 이상
2. 아이콘 전용 버튼은 `aria-label` 제공
3. 키보드만으로 주요 기능 접근 가능
4. 입력은 placeholder만 두지 말고 라벨 제공
5. skip link 제공
6. heading hierarchy 유지
7. 색상만으로 정보 전달 금지
8. 의미 있는 이미지는 alt 제공
9. 오류 메시지는 `role="alert"` 또는 `aria-live` 사용

## 8. 화면별 적용 기준

### 8.1 대시보드

1. 필터 바 1행
2. KPI 카드 2행
3. 차트 2개 이상 병렬
4. 하단 상세 표 또는 예외 목록

### 8.2 인력 관리

1. 상단 액션 버튼은 우측 정렬
2. 프로필 액션은 아이콘 버튼으로 통일
3. 상세 화면은 이력 패널 2열 구조 유지

### 8.3 근무지 관리

1. 1단계와 2단계를 시각적으로 명확히 분리
2. 시뮬레이션 결과는 달력과 통계를 함께 표시
3. 드래그 앤 드롭 영역은 컬럼별 높이를 통일

### 8.4 실적 관리

1. 근무지 그룹 아코디언 구조 유지
2. 근로유형과 공휴일 여부는 배지 체계로만 표시
3. 승인/반려 액션은 한 줄에서 즉시 식별 가능해야 한다.

### 8.5 수당 관리

1. 좌측 비교 차트 + 우측 상세 표 구조 유지
2. 가로 막대 차트가 기본
3. 수당유형 drill-down 시 누적 막대 전환 허용

### 8.6 운영 관리

1. 공휴일/요율/사용자/양식 화면은 동일한 설정형 레이아웃을 재사용
2. 상단 필터와 하단 저장 액션 위치를 통일

## 9. 구현 메모

React 구현 시 아래를 권장한다.

1. 검색 입력은 `useDeferredValue` 또는 debounce 사용
2. 테이블, 필터 바, KPI 카드, 상태 배지는 공용 컴포넌트로 분리
3. CSS 변수 또는 토큰 객체를 통해 색상값을 직접 하드코딩하지 않는다.

## 10. Do / Don't

Do:

1. 화이트 카드와 블루 액센트로 정돈된 라이트 모드를 유지한다.
2. 숫자, 시간, 금액은 정렬과 단위 표기를 일관되게 맞춘다.
3. 복잡한 데이터는 카드보다 표와 비교 차트에서 해결한다.

Don't:

1. 보라색 SaaS 그라디언트를 섞지 않는다.
2. 테이블과 카드마다 다른 라운드 값을 쓰지 않는다.
3. 상태를 색상만으로 구분하지 않는다.
4. 원형 차트를 기본 비교 차트로 쓰지 않는다.
