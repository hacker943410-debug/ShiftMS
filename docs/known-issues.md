# 알려진 이슈

## 2026-03-24 기준

### 1. 운영 관리 실데이터 확인 미완료
- 공휴일, 요율, 양식, `DB업데이트` 흐름은 자동 smoke 기준으로 정리됐지만 실제 운영 데이터 기준 수동 확인이 아직 남아 있다.
- 수동 확인은 `docs/operations-manual-qa-checklist.md` 기준으로 진행한다.
- 현재 release 브랜치 분기를 막는 유일한 잔여 blocker 는 이 수동 QA 기록이다.
- 수동 QA에서 문제 없으면 이 항목은 릴리즈 시 제거 대상이다.

### 2. Access 기반 DB업데이트 범위 제한
- Access 기반 복원은 `공휴일 / 요율 / 근무지 / 인력 / 시급 / 패턴 / 배정 종료일` 과 `사업조직별근무실적` 기반 기본 승인/수당 이력을 반영한다.
- Access 승인 이관 중 `SK증권 홍길동1 2024-08-15` 1건은 시급을 복원하지 못해 승인/수당 이력을 생성하지 않는다.
- 양식 이력과 출력 이력은 Access 원본 구조에 없어서 복원 대상에 포함하지 않는다.
- 패턴은 `대전DC`, `대전NOC`, `울산CLX` 를 원본 시간 슬롯 부재로 제외한다.

### 3. Windows 전용 릴리즈 흐름
- 현재 릴리즈 산출물은 Windows NSIS 설치본 기준으로만 정리돼 있다.
- macOS, Linux용 설치본은 범위에 포함하지 않았다.

### 4. 설치본 자동 검증 범위
- `release:verify-package` 로 NSIS 설치/실행과 unpacked 실행 smoke까지 자동화했다.
- 실제 운영 PC에서의 권한 정책, 백신 예외, 네트워크 폴더 정책은 별도 현장 검증이 필요하다.

## 비고
