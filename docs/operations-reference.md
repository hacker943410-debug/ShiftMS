# 운영 참고서

## 문서 역할
- 이 문서는 `DB업데이트`, 수당 계산, 양식 관리처럼 운영 기준이 필요한 항목만 모아 둔 요약 문서다.
- 실운영 검수 기록은 `docs/operations-manual-qa-checklist.md` 에 남기고, 릴리즈 판단은 최신 릴리즈 문서에 반영한다.

## 1. `DB업데이트` / 복원 기준

### 대상 원본
- 운영 DB 백업 JSON `.json`
- 운영 기준 Access DB `.accdb`
- Excel 파일은 운영자가 임의로 DB를 핸들링할 수 있으므로 `DB업데이트` 복원 입력으로 사용하지 않는다.

### 현재 복원 범위
- JSON 백업: 백업 스냅샷에 포함된 SQLite 테이블을 현재 앱 스키마 기준으로 그대로 복원하고, 현재 경로 설정은 유지한다.
- Access DB: 공휴일, 요율, 근무지, 인력, 시급, 패턴, 배정 종료일, `사업조직별근무실적` 기반 기본 승인/수당 이력을 현재 앱 스키마로 변환해 복원한다.
- 공휴일
- 요율
- 근무지
- 인력
- 시급
- 패턴
- 배정 종료일
- `사업조직별근무실적` 기반 기본 승인/수당 이력

### 현재 복원 비포함
- 양식 이력
- 출력 이력
- 원본 Access 파일 자체 재생성

### 핵심 매핑 규칙
1. `공휴일` 은 연도별 전체 교체 방식으로 반영한다.
2. `연장근로요율` 은 앱 기본값이 아니라 JSON 백업값을 그대로 저장 기준으로 쓴다.
3. `사업조직별근무자현황` import 시 빈 슬롯 행(`None_*`, `공석`, `TBD`, 무사번`)은 제외한다.
4. Access DB 직접 확인 결과 `사업조직별근무자현황` 에는 직급 컬럼이 없으므로, `사업조직별근무실적.직급명` 단일 컬럼만 `사원 / 대리 / 과장 / 차장 / 부장` 선택값으로 정규화해 저장한다.
5. 인력 기본정보 직급은 `사업조직별근무실적` 을 사원번호로 묶고 최신 `근무날짜` 행의 `직급명` 으로 보강한다.
6. 기존 `department` 저장/표시 호환은 변경하지 않고, 새 직급 필드는 별도 컬럼으로 분리한다.
7. `근무자별시급관리` 는 1차 기준으로 `적용유무=True` 인 최신 활성 시급을 우선 반영한다.
8. `직무해제자현황` 은 `retireDate` 가 아니라 `employee_site_assignments.end_date` 로만 반영한다.
9. `사업조직별근무실적` 은 `근무지 + YYYY-MM + 승인상태` 기준 synthetic file 로 변환해 반영한다.
10. Pool 대체근무는 기록에는 남기되 화면/수당 대상에서는 제외한다.
11. `A / B / C` 같은 조명은 현재 앱에서 `A조 / B조 / C조` 로 정규화한다.

### 현재 제한
1. `SK증권 홍길동1 2024-08-15` 1건은 시급을 복원하지 못해 승인/수당 이력을 생성하지 않는다.
2. `대전DC`, `대전NOC`, `울산CLX` 패턴은 원본 시간 슬롯 부재로 제외한다.
3. Access DB `.accdb` 복원은 대상 PC에서 `ACE OLEDB`를 사용할 수 있어야 한다. 없으면 설치 단계 경고와 `DB업데이트` 미리보기 사전 점검에서 안내한다.
4. 운영 PC 권한 정책, 백신 예외, 네트워크 폴더 정책은 별도 현장 검증이 필요하다.
5. 운영 DB 백업은 JSON과 Excel `.xlsx` 형식으로 함께 저장되고, Access 원본 경로가 확인되면 `.accdb` 사본도 함께 보관한다.
6. `DB업데이트` 복원 입력은 JSON `.json` 백업 파일 또는 Access DB `.accdb` 파일을 사용한다.

### 권장 실행 순서
1. 경로 설정 저장
2. Access 또는 JSON 기준 `DB업데이트` 미리보기 확인
3. Excel 파일이 복원 입력으로 선택되지 않는지 확인
4. 공휴일 / 요율 / 인력 / 패턴 / 승인 기본 이력 sanity check

## 2. 수당 요율 / 계산 기준

### 요율 구조
수당 요율은 `근로유형 5행 x 기본/연장/야간 3열` 구조로 관리한다.

| 근로유형 | 기본 | 연장 | 야간 |
| --- | --- | --- | --- |
| 법정공휴일 | 1.5 | 1.5 | 1.5 |
| 평_대체근로수당 | 1.5 | 2.0 | 2.5 |
| 휴_대체근로수당 | 1.5 | 2.0 | 2.5 |
| 평_연장근로수당 | 0 | 1.5 | 2.0 |
| 휴_연장근로수당 | 0 | 0 | 0 |

### 요율 운영 규칙
1. 요율 수정과 적용 시 변경 사유 입력은 필수이며, 입력한 사유는 `최근 요율 변경 이력`과 활동 이력에 함께 남는다.
2. 기존 요율을 수정할 때 `적용 시작일`은 오늘 이전 날짜로 변경할 수 없다.
3. 이미 시작된 요율은 `적용 시작일` 자체를 변경할 수 없다.
4. JSON 백업/복원에는 요율 버전과 함께 요율 변경 이력도 포함된다.

### 시간 분해 기준
1. 야간근로시간: `22:00 ~ 06:00`, 휴게시간은 야간에서 우선 차감
2. 기본근로시간: 비야간 근로시간 중 최대 8시간
3. 연장근로시간: 기본근로시간 8시간을 채우고 남은 비야간 근로시간
4. `기본 + 연장 + 야간 = 총근로시간` 이 되도록 유지

### 근로유형 매핑
- `법정공휴일`, `공휴일`, `휴일근로` -> `법정공휴일`
- `평_대체`, `대체근로` -> `평_대체근로수당`
- `휴_대체` -> `휴_대체근로수당`
- `평_연장`, `연장근로` -> `평_연장근로수당`
- `휴_연장` -> `휴_연장근로수당`

### 출력/집계 규칙
- `법정공휴일` -> 법정공휴일수당
- `평_대체근로수당`, `휴_대체근로수당` -> 대체근로수당
- `평_연장근로수당`, `휴_연장근로수당` -> 연장근로수당
- 화면/별첨 표기는 `대체근무`, `연장근무`, `법정휴일근무` 라벨을 사용한다.

### 예외 규칙
- Pool 근무자의 대체근무는 실적 기록에는 남기지만 수당 계산/집계/품의 출력에서는 제외한다.
- 주간고정조(FIXED_DAY) 근무자의 교대조 대체근무도 Pool과 동일하게 제외한다. 아래 `대체근무수당 제외 정책` 참고.
- 임의 시급 재승인 행은 최신 승인 스냅샷의 시급을 우선 사용한다.
- 퇴직자 선지급 건은 일반 지급 합계와 품의서 2번 항목에서 제외하고, 품의서 3번 항목으로 별도 집계한다.

### 대체근무수당 제외 정책
조 이름(`A조`, `Pool` 등)이 아니라 근무지 패턴에 저장된 **조별 근무유형**으로 판단한다.

| 조별 근무유형 | 의미 | 교대조 근무를 대체했을 때 |
| --- | --- | --- |
| `POOL` | Pool 조 | 대체근무수당 미지급 (기존 규칙) |
| `FIXED_DAY` | 주간고정조 | 대체근무수당 미지급 (신규) |
| `ROTATING` | 주야 교대조 | 기존 지급 규칙 적용 |

1. 판정 순서: 관리자 수동 제외 -> 대체 대상이 교대조 근무인지 -> 본인 정규근무가 아닌 추가근무인지 -> 대체자의 근무유형(POOL / FIXED_DAY / ROTATING).
2. 판정 결과는 사유 코드(`POOL_SUBSTITUTE_EXCLUDED`, `FIXED_DAY_SUBSTITUTE_EXCLUDED`, `ROTATING_SUBSTITUTE_ELIGIBLE`, `NOT_ADDITIONAL_WORK`, `TARGET_IS_NOT_ROTATING_SHIFT`, `MANUAL_EXCLUSION`, `NO_ALLOWANCE_POLICY`)와 함께 실적 행에 저장되고, 실적 관리 화면에서 사유를 확인할 수 있다.
3. 대체자의 근무유형은 **대상 날짜에 유효한 배정 이력**의 조로 판정한다. 현재 소속이 바뀌어도 과거 근무일의 판정은 그대로다.
4. 신규 제외 규칙은 `운영 관리 > 경로 설정 > 대체근무수당 제외 정책`의 `적용 시작일` 이후 근무일부터만 적용한다. 시작일이 비어 있으면 신규 규칙을 적용하지 않는다. Pool 제외는 시작일과 무관하게 항상 적용된다.
5. 기존 지급 결과는 일괄 재계산하지 않는다. 이미 저장된 수당 계산 행은 그대로 유지된다.

### 조별 근무유형 설정 위치
`근무지 관리 > 근무지 등록/수정 > 1단계 패턴 등록 > 기본 설정 > 조 관리`에서 조마다 지정한다.

| 항목 | 뜻 | 반영되는 곳 |
| --- | --- | --- |
| 조 이름 | 화면에 표시할 이름(비우면 `A조` 같은 기본 이름) | 1단계 달력 미리보기, 근무 묶음 배정 칩 |
| 근무유형 | `Pool` / `주간고정조` / `교대조` | 대체근무수당 제외 정책 판정 |
| 근무 묶음 | 이 조가 따를 근무 패턴 묶음 | 근무표 자동 생성, 달력 미리보기 |
| 사용 | 끄면 그 조는 근무표·달력에서 빠진다 | 근무표 생성 대상, 조 배정 화면 |
| 순서(위/아래) | 조가 보이는 차례 | 달력 미리보기, 근무 묶음 배정, 2단계 조직 구성 |

1. 조를 늘리거나 줄이는 것은 `조 수` 입력으로 한다. 조 수를 줄여도 남는 조의 이름·근무유형·순서는 그대로 유지된다.
2. `별도 근무 적용 유무`를 켜면 `Pool` 조가 목록 맨 앞에 생긴다(Pool → A조 → B조 …).
3. Pool 성격 조만 근무 묶음을 `배정 안 함`으로 둘 수 있다. 배정 안 하면 근무표 자동 생성에서 빠진다(기존 Pool 동작과 같다). 교대조·주간고정조는 반드시 묶음이 하나 배정된다.
4. 조 이름이 서로 겹치면 저장되지 않는다. 모든 조를 `사용 안 함`으로 둘 수도 없다.

## 3. 승인 / 마감 운영 규칙

### 실적 파싱 선행 조건
1. 실적 파일 파싱은 해당 월/근무지의 배포 또는 저장 완료된 월간 근무표를 기준 데이터로 사용한다.
2. 법정휴일근무와 대체근무 행은 회수된 실적 파일의 이름/날짜/직원명만으로 시간을 확정하지 않고, 저장된 월간 근무표의 `dutyCode`, 시작/종료 시각, 휴게시간과 매핑해 산출한다.
3. 해당 월/근무지의 저장 근무표가 없으면 법정휴일근무/대체근무의 근무시간을 복원할 수 없어 0시간 및 경고 행이 발생할 수 있다.
4. 따라서 운영 순서는 `근무표 배포 및 저장 -> 회수 실적 파일 승인대기 폴더 적재 -> 실적 관리 파싱/승인`을 기준으로 한다.

### 실적 재승인
1. `승인완료` 조회는 승인 완료 폴더의 실제 보관본만 확인하는 용도다.
2. `근무지 반려` 후 재승인 진행 중인 최신 파일은 승인 대기 쪽에서만 확인한다.
3. 재승인 확정은 현재 파일의 `변경 가능` 행이 모두 현재 사이클 기준으로 다시 승인된 경우에만 허용한다.

### 수당 반려 / 품의 승인
1. `근무지 반려`는 사유 입력이 필수이며, 반려 사유는 승인 이력에 그대로 남긴다.
2. `품의승인` 상태 수당이 포함된 근무지는 최종 마감 건이 섞인 상태이므로 `근무지 반려`를 실행할 수 없다.
3. 품의 승인 시 문서 출력과 자동 백업이 먼저 수행된 뒤, `품의 승인 기록 저장 + 수당 상태 proposal-approved 전환`을 SQLite 트랜잭션으로 한 번에 반영한다.
4. 품의 승인 중 DB 반영이 실패하면 출력 문서와 백업 파일은 남을 수 있으나, 수당 상태와 품의 승인 기록은 되돌린다. 운영자는 출력물/백업 파일을 확인한 뒤 품의 승인을 다시 시도한다.

## 4. 양식 관리 기준

### 지원 양식
- 근무표 양식 1: `근무표_템플릿1.xlsx`, `sample1`, 일반형
- 근무표 양식 2: `근무표_템플릿2.xlsx`, `sample2`, 6조 2교대형
- 기본 품의서: `품의서_2026-04_수정본.xlsx`, 2026-04 compact 지급/조기 지급/총 합계 구조
- 기본 별첨1: `별첨1_2026-04_수정본.xlsx`, 최종 출력은 `별첨1` 단일 시트
- 별첨2: `별첨2_샘플.xlsx`
- 품의서, 별첨1, 별첨2는 같은 승인형 등록 흐름을 사용한다.

### 공통 원칙
1. 운영 중인 양식 파일을 직접 덮어쓰지 않는다.
2. 양식 수정은 항상 `새 파일 + 새 버전`으로 등록한다.
3. 승인된 양식만 실제 배포/출력 메뉴에서 선택된다.
4. 이미 저장된 산출물은 저장 당시의 `templateVersionId` 를 계속 사용한다.
5. 구조가 달라지면 새 계열로 보고 preview/export 알고리즘과 테스트를 같이 수정한다.
6. 별첨1 출력은 원본 수정본의 검증/인력현황/계산식 시트를 최종 파일에 포함하지 않는다.
7. 별첨1 상세 표 D열은 승인/수당 스냅샷의 직급을 출력하고, 직급이 없으면 `-` 로 표시한다.
8. 별첨1 수당 금액은 양식 샘플 수식이 아니라 앱 계산 결과 기준 `시급 * 요율 * 시간` 원 단위 올림으로 기록한다.
9. 별첨1 조기 지급 대상이 없을 때 `해당 없음` 행을 출력하되, 근무시간/수당/요율/시급/지급비용 영역 `H:S`는 Blank로 둔다.
10. 별첨1 하단 계산식 영역은 기본 샘플 `별첨1` 시트 `24:45`행의 문구, 병합, 테두리, 배경색, 폰트색, 굵기, 크기, 행높이를 그대로 복제한다.

## 5. 사이트 명 관리 기준

### 목적
- `사이트 명 관리`는 근무지 등록 1단계에서 선택할 사이트 명 목록을 관리한다.
- 선택된 사이트 명은 품의서 출력에서 고객사명과 근무지명을 분리 표기하는 기준으로 사용한다.

### 운영 규칙
1. 새 고객사 또는 사이트 구분값은 `사이트 명 추가`로 등록한다.
2. 이미 근무지에서 사용 중인 사이트 명은 삭제하지 않고 명칭 수정으로 관리한다.
3. 사용 근무지가 0건인 사이트 명만 삭제할 수 있다.
4. 근무지 등록 또는 수정에서 사이트 명을 바꾸면 이후 새로 출력하는 문서의 고객사/근무지 구분 기준에 반영된다.
