# 규칙 대장 (무엇이 규칙이고 어디가 함정인가)

> **이 폴더의 목적**: 어떤 질문이 들어왔을 때 **코드를 다시 다 읽지 않고 답하기 위한 사전**이다.
> `docs/codebase-map.md`는 **어디에 있나**(위치)를 답하고, 여기는 **무엇이 규칙인가**(동작)를 답한다. 둘은 짝이다.

## 왜 만들었나

2026-09-04, "시급 관련 문제가 생겼다"는 조사 요청 하나에 **에이전트 235개 · 2,400만 토큰**이 들었다.
위치를 못 찾아서가 아니었다. 위치는 코드맵으로 5분이면 찾는다. 돈이 나간 곳은 그 다음이었다 —
**"그래서 규칙이 뭔데? 함정은 어디야?"** 가 어디에도 적혀 있지 않아 코드를 처음부터 다 읽어야 했다.

그 답을 여기 적어 둔다. 다음부터는 이 폴더의 해당 문서 **한 장**만 읽고 답한다.

## 쓰는 법

1. `docs/codebase-map.md` 2장 "운영자 말 → 찾아갈 곳"에서 영역을 정한다.
2. 그 줄이 이 폴더의 문서를 가리키면 **그 문서를 먼저 읽는다**.
3. 문서에 답이 있으면 끝이다. 없으면 그때 코드로 간다.
4. 코드로 갔다면 **알아낸 것을 반드시 이 폴더에 적어 넣고** 끝낸다. 그래야 다음 사람이 또 안 판다.

## 새 문서를 쓸 때 지킬 형식

- **규칙(R-n)** 과 **함정(T-n)** 을 나눈다. 규칙 = 설계대로 동작하는 것. 함정 = 화면 안내와 실제가 다르거나, 운영자가 사고를 낼 수 있는 것.
- 항목마다 세 줄을 반드시 넣는다:
  - **규칙** — 조건·순서·예외를 정확히
  - **운영자에게** — 기술용어 없이 쉬운 말로 (루트 `CLAUDE.md` 규칙)
  - **근거** — `파일:줄번호`. 줄번호가 없으면 다음 사람이 못 믿는다.
- 함정에는 **[치명]/[높음]/[보통]/[낮음]** 을 붙인다.
- 확인 못 한 것은 **[미확인]** 으로 남긴다. 빈칸보다 낫다.
- 조사에서 실측한 수치가 있으면 **날짜와 함께** 적는다(데이터는 변한다).

## 유지 규칙

- 그 영역의 코드를 고치면 해당 문서의 줄번호와 규칙을 같이 고친다.
- 규칙이 시험으로 못 박혀 있으면 시험 파일을 근거에 함께 적는다. **시험이 곧 규칙 문서**다.
- 문서에 적힌 것과 코드가 다르면 **코드가 정답**이다. 발견 즉시 문서를 고친다.
