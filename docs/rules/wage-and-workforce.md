## 1. 규칙 (설계대로 동작하는 것)

### R-1. 입사일은 신규 등록 창에서만 입력하고, 필수이며, 기본값은 오늘
등록 창을 열면 입사일이 **오늘(한국 날짜)** 로 채워진다. 비우면 저장되지 않는다.
- **운영자에게**: 등록할 때 입사일을 반드시 넣어야 하고, 안 고치면 오늘 날짜로 들어갑니다.
- **근거**: `WorkforceManagementScreen.tsx:692-697`(모달 열 때 오늘로 초기화) · `:855-866`(필수 검증) · `:2195-2203`(입력칸) · `shared/lib/local-date.ts:5-8`(오늘 = 로컬 날짜, UTC 아님)

### R-2. 등록 창에 넣은 통상시급의 적용 시작일은 '오늘'이 아니라 '입사일'이다
등록 시 시급을 함께 넣으면 시급 이력 첫 줄이 자동 생성되는데, 그 적용일은 입사일이다. 종료일은 비어 있고(계속), 사유는 `"직원 등록/수정"` 고정.
- **운영자에게**: 입사일을 과거로 넣으면 시급도 그 과거 날짜부터 소급 적용됩니다. 경고는 뜨지 않습니다.
- **근거**: `employee-storage-service.ts:557-584`, 적용일은 `:579` (`input.hireDate ?? updatedAt.slice(0,10)`)

### R-3. 첫 근무지 배정은 근무지와 근무조를 **둘 다** 골랐을 때만 생기고, 시작일은 입사일이다
근무조명이 공백이면 배정이 아예 만들어지지 않는다.
- **근거**: `employee-storage-service.ts:459-461`(조건) · `:550`(start_date = 입사일) · `shared/domain/team-label.ts:7-23`(공백 정규화)

### R-4. BP 인력은 등록 화면에서 사번·시급을 넣을 수 없다
BP를 고르면 두 칸이 잠기고 이미 입력한 값도 지워진다. 사번은 내부용으로 자동 생성되고, **시급 이력 0줄로 시작**한다. 단 이 제한은 화면에만 있고 저장 로직에는 없다.
- **근거**: `WorkforceManagementScreen.tsx:549-563`(값 지움) · `:868-871`(저장 요청에서 제외) · `:2132`·`:2260`(칸 잠금)

### R-5. 인력 표가 완전히 비었을 때만 시연용 기본 인력 3명이 생긴다
`2026-01-01`이라는 날짜는 그 시드 안에서만 쓰이는 예비값이며 실제 등록에는 관여하지 않는다.

### R-6. 시급은 값 하나가 아니라 '적용일 ~ 종료일' 구간의 목록이다
종료일이 비어 있으면 계속 유효하다는 뜻.
- **근거**: `sqlite-storage-service.ts:92-100`(wage_rates 정의) · `:102-103`(인덱스는 유니크 아님 — 겹침을 DB가 막지 않는다)

### R-7. 저장 알고리즘 — 같은 날짜면 덮어쓰고, 앞줄은 전날로 끊고, 새 줄은 다음 줄 전날까지
1. 그 인력의 모든 시급 줄을 시작일 오름차순으로 읽는다.
2. **시작일이 같은 줄이 있으면** 새 줄을 만들지 않고 그 줄의 금액·사유·종료일을 고쳐 쓴다.
3. 없으면: 새 시작일을 걸치고 있는 앞줄(`시작일 < 새 시작일` 이고 `종료일이 비었거나 새 시작일 이후`)을 **새 시작일의 전날**로 끊는다.
4. 새 줄의 종료일은 **다음 줄 시작일의 전날**(다음 줄이 없으면 비움).
- **운영자에게**: 그래서 기간이 겹치는 일은 구조적으로 생기지 않습니다. 대신 **같은 날짜로 다시 저장하면 이전 금액이 어디에도 남지 않습니다.**
- **근거**: `employee-history-service.ts:375-444` — `:392`(같은 날짜 찾기) · `:394-395`(다음 줄) · `:399-411`(덮어쓰기) · `:416-422`(앞줄 끊기) · `:424-442`(새 줄 넣기)

### R-16. 일괄 적용 엑셀 읽기 규칙
- 첫 번째 시트만, **데이터는 무조건 2행부터**. 1행은 **머리글 줄로만** 쓰인다(데이터로 읽지 않는다).
- 읽는 칸은 **사번(선택)·근무지명·이름·시급 네 개**.
- **파일을 고르면 1행 머리글을 읽어 열을 자동으로 채운다**('사번'·'사원번호'·'근무지명'·'성명'·'통상시급' 등). 규칙 세 가지:
  1. **머리글이 이름을 댈 때만** 채운다. 자리(A열이니까 사번이겠지)로 넘겨짚지 않는다.
  2. **같은 이름의 머리글이 두 열에 있으면 그 칸을 비워 두고** 후보 열을 화면에서 알린다(옛 시급·새 시급이 나란히 있는 파일 대비). 필수 칸(근무지명·이름·시급)이 비어 있으면 **[미리보기] 자체가 잠긴다** — 운영자가 고르기 전에는 아무것도 못 돌린다.
  3. 못 찾은 항목은 **기본값(B/C/D)** 을 넣고 "확인하세요"라고 알린다. **직전 파일의 값을 물려주지 않는다.**
- 머리글 읽기 결과는 **그 파일 것일 때만** 반영된다. 파일을 연달아 고르거나, 운영자가 열을 손으로 고치거나, **이미 미리보기·적용이 시작됐으면** 늦게 도착한 옛 결과는 버려진다(매핑 세대 규칙, `reduceWageBulkMapping`).
- 사번 머리글이 없으면 비워 두고 **"사번 없이 찾으면 사람이 빠질 수 있다"** 고 경고한다. 열 글자는 언제든 손으로 고칠 수 있다.
- 금액은 쉼표·공백·'원'만 지우고 숫자로 변환. 0 이하는 오류, **소수점은 그대로 통과**.
- 같은 사람이 두 번 나오면 **첫 줄이 이긴다**.
- 적용일은 행별이 아니라 **모달 전역 하나**, 기본값 오늘.
- **근거**: `workforce-wage-bulk-update-service.ts:38`·`:72-82`·`:94-101`·`:204-226`·`:356-376` · `WorkforceManagementScreen.tsx:110-114`

### R-17. 일괄 적용 미리보기 상태값 9종
`적용 가능` `적용 완료` `필수값 누락` `시급 형식 오류` `일치 인력 없음` `동일 인력 중복` `퇴사자 제외` `기존 시급과 동일` `중복 항목`.
'기존 시급과 동일'은 **오늘 시급이 아니라 고른 적용일 그 날에 유효했던 시급**과 비교한다.

### R-20. 옛 프로그램(Access) 이관 규칙 — 여기서 대부분의 과거 데이터 문제가 나온다

## 2. 함정 (화면 안내와 실제가 다르거나, 사고가 나는 곳)

### T-1. [치명] ✅고침(안내만) 시급을 고쳐도 이미 불러온 승인 대기 실적의 금액은 그대로다
시급은 실적 엑셀을 **처음 읽는 순간** 각 줄에 박혀 저장된다(R-9). 그 뒤 시급 장부를 고쳐도 이미 목록에 있는 줄은 저절로 바뀌지 않는다. 시급 변경은 재분석 표식을 전혀 남기지 않고, 엑셀 파일이 그대로면 저장된 옛 분석 결과를 재사용한다.
- **지금(패치 후)**: 안내 문구가 사실대로 말한다 — "자동으로 바뀌지 않습니다. 실적 관리 화면에서 새로고침(↻)으로 다시 읽어야 반영됩니다. 다만 그 파일에서 일부만 승인해 뒀다면 이미 승인한 줄도 재검토로 되돌아갑니다."(T-2 위험까지 함께 알린다)
- **아직 남은 것**: 자동 재계산은 넣지 않았다. 넣으면 T-2가 터진다. 운영자가 ↻를 직접 눌러야 한다.
- **옛 결함(0.5.4 배포판)**: `"아직 승인하지 않은 실적은 새 시급으로 다시 계산됩니다"` 라고 **반대로** 안내했다.
- **근거**: 문구 `WorkforceManagementScreen.tsx`의 `WAGE_CHANGE_REFRESH_NOTICE` · 시급이 실적에 박히는 지점 `schedule-return-performance-parser.ts:424-438` · `performance-file-storage-service.ts:558`

### 5-1. Codex 적대검증에서 더 잡힌 것 (같은 브랜치, R1~R8 여덟 차례)

첫 패치는 통과하지 못했다. 여섯 번의 검증에서 **30건**이 더 나왔고 전부 실재였다 — 그중 스물셋은 그 패치들이 새로 만든 결함이었다. **되풀이되는 유형은 둘**: ①늦게 도착한 비동기 응답을 현재 화면에 묶지 않는 것(미리보기 → 적용 → 머리글 읽기, 세 번 반복) ②안전장치를 만들어 놓고 그 결과가 실제로 흐르는지 확인하지 않는 것. **가장 위험했던 것은 R5 #1** — 내가 "사번 오타를 막는 안전장치"라고 쓴 코드가, 대소문자만 다른 사번이 함께 있으면 **오히려 엉뚱한 사람의 시급을 조용히 바꾸는 경로**였다.

| 무엇 | 어떻게 고쳤나 |
|---|---|
| 일괄 미리보기 응답이 늦게 도착해 **낡은 표가 되살아남**(적용일·열 변경, **파일 교체**, 모달 재진입 전부) | 미리보기가 **자기가 만들어진 기준(파일·적용일·열)** 을 들고 다니게 하고, 기준이 다르면 화면에 보이지도 적용되지도 않게 했다(`wage-bulk-preview-basis.ts`). 무효화를 "잊지 않기"에 기대지 않는 구조 |
| 같은 적용일 줄이 둘일 때 **저장은 옛 줄, 화면·계산은 새 줄** | 저장이 읽기와 같은 줄(생성 늦은 쪽)을 고르게 함 |
| 같은 **미래** 적용일이 둘일 때 '예정' 표시만 옛 줄을 고름 | `findUpcomingWageRate`의 동률 규칙을 읽기와 맞춤 |
| 이력에 공백이 있으면 앞줄이 안 끊기는데 **끊긴다고 예고** | 미리보기 조건을 저장 SQL과 동일하게 |
| 오늘 유효한 시급이 없는데 **종료일만 '계속'** | `-`로 |
| 새로고침 안내가 **T-2 위험을 안 말함** | 문구에 "부분 승인 파일은 이미 승인한 줄도 재검토로 되돌아간다"를 넣음 |
| 자정에 예정 시급이 활성화되면 **입력 중이던 폼이 초기화** | 불필요한 의존성 제거 |
| 문서가 ✅만 붙이고 옛 결함을 현재형으로 서술 / 줄번호 근거가 이미 낡음 | 3단(지금/남은 것/옛 결함) 구조 + 근거를 **함수·시험 이름**으로 |
| 새 코드 주석이 한국어(레포 규칙 위반) | 이 브랜치 주석은 영어로. 기존 755줄은 별건 |

**R3에서 더 나온 3건**

| 무엇 | 어떻게 고쳤나 |
|---|---|
| 보호가 **미리보기에만** 걸려 있어, 적용 중 입력을 바꾸면 A 저장 결과가 B 파일·B 날짜 옆에 표시됨 | 적용 결과도 기준을 들고 다니게 하고, **무엇을 화면에 보일지 판정 자체를 순수 함수로 뗐다**(`selectWageBulkView`). 적용 중에는 입력·닫기도 잠근다 |
| 미리보기 뒤 **같은 경로의 파일 내용이 바뀌면** 안 본 내용이 적용됨 | 미리보기 판정의 지문을 만들고, 적용은 그 지문과 맞을 때만 실행(T-18-1) |
| 퇴사일 **동률 경계**가 근무표·실적 판정과 반대 | `<=` 로 맞추고 동률 시험 추가(T-18) |

**R6에서 더 나온 5건**

| 무엇 | 어떻게 고쳤나 |
|---|---|
| 머리글 읽기 결과가 **현재 파일에 묶여 있지 않음**(A→B 연속 선택 시 A 응답이 B를 덮음, 수동 입력도 덮음) | 매핑 세대 카운터 도입, `resolveWageBulkColumnSuggestion`이 세대가 다르면 버림 |
| 일부 머리글 미탐지 시 **직전 파일의 열을 물려받음** | 새 파일은 **기본값(B/C/D)** 에서 시작. 못 찾은 항목을 화면에 나열 |
| 이력 공백 구간에서 **끊기지도 않을 종료일을 표시**(T-6의 일괄판 재발) | `truncatedRates`가 비면 `-`, 여럿이면 개수까지 |
| 같은 머리글이 두 열이면 **조용히 첫 열 선택** | 자동 선택 안 하고 화면에서 알림(`ambiguousFields`) |
| 규칙 문서 R-16이 "머리글 자동 인식 없음"이라 **T-7과 모순** | R-16·상세 가이드 전부 갱신 |

**R5에서 더 나온 7건**

| 무엇 | 어떻게 고쳤나 |
|---|---|
| 🔴 대소문자만 다른 사번 + 퇴사자 조합에서 **엉뚱한 재직자 시급이 바뀜** | 사번 경로를 **한 명으로 좁힌 뒤에** 이름·퇴사를 본다. 정확 철자 우선, 대소문자 충돌은 수동 확인 |
| 지문이 **끊길 앞줄 전체**를 못 박지 못함 | `savePlan`에 끊길 줄들의 id·현재 종료일까지 포함 |
| 같은 시작일 덮어쓰기를 **참/거짓**으로만 기록 | 실제 덮어쓸 줄의 **id**를 기록 |
| 새 저장 기간이 **화면에 안 보임** | '이전 시급 종료일'·'새 시급 종료일' 분리, 덮어쓰기 딱지(T-18-2) |
| 무배정 인력에 **파일의 근무지가 실제 근무지처럼** 표시됨 | '미배정'로 표시 |
| 사번 열 기본 빈칸 = 사용자 요구('사번 기준')와 불일치 | **머리글 자동 인식**으로 기본 적용, 못 찾으면 경고 |
| stale 배선·함수형 오류코드 시험 없음 | 적용 응답 처리를 `resolveWageBulkApplyAnswer`로 떼어 시험, helper 시험 추가 |

**R4에서 더 나온 4건**

| 무엇 | 어떻게 고쳤나 |
|---|---|
| 지문 불일치로 **적용이 거부돼도** 무효가 된 미리보기와 [적용] 버튼이 화면에 남음 | 전용 오류 코드로 판별해 미리보기를 폐기 → 다시 만들기 전엔 적용 불가 |
| 지문이 **저장 기간을 정하는 미래 시급**을 안 담음(적용 사이에 미래 시급이 생기면 종료일이 달라짐) | 저장 계획(새 줄 종료일·같은 시작일 덮어쓰기 여부)을 미리보기 행에 넣어 지문에 포함 |

**R7에서 더 나온 4건 + 실앱 대조에서 1건**

| 무엇 | 어떻게 고쳤나 |
|---|---|
| 미리보기·적용을 **시작한 뒤** 도착한 머리글 응답이 열 칸을 덮음(같은 유형 네 번째) | 세대 증가를 호출부에서 빼고 **매핑 수명주기 전체를 리듀서 하나**(`reduceWageBulkMapping`)로 옮김. 시험이 이벤트를 직접 흘려보냄 |
| 모호한 머리글 칸에 **기본값 D를 채움**(사실상 위치 추측) | 모호한 칸은 **빈칸**, 필수 칸이 비면 [미리보기] 잠금 |
| 단건 저장이 겹친 과거 이력 여러 줄 중 **한 줄만** 끝난다고 안내 | `previousRates`로 걸치는 줄 전부, 일괄과 같은 규칙 |
| 실앱: 배정 없는 인력의 근무지 칸이 **'미배정'이 아니라 빈칸** — `?? "미배정"`이 빈 문자열을 통과시킴 | 조회는 빈 값을 undefined로, 표시는 `||`로. **코드만 읽고 고쳤다고 단정한 결함** |

**R8에서 더 나온 5건**

| 무엇 | 어떻게 고쳤나 |
|---|---|
| 기본값 B/C/D가 완전한 매핑이라 **머리글을 읽는 동안에도 [미리보기]가 살아 있음** — 바로 누르면 확인 안 된 열로 미리보기하고 자동 인식 응답은 버려짐 | 매핑 모델에 **읽는 중/읽음/실패** 상태. 읽는 동안 [미리보기] 잠금("머리글 확인 중..."), 실패는 조용히 버리지 않고 "기본값을 넣었으니 확인하라"고 말함. 실앱 캡처가 잠금 순간을 잡음 |
| 열 하나를 손으로 고치면 **아직 사실인 다른 경고**(사번 없음)까지 사라짐 | 안내를 문장 하나가 아니라 **사실 목록**(`headerFacts`)으로 보존하고, 고친 칸의 문장만 물림(`describeWageBulkMapping`) |
| 선택 열인 사번만 중복일 때 "직접 넣어야 미리보기를 만들 수 있다"고 **버튼과 모순되는 안내** | 사번 전용 문구: "비워 두면 근무지명+이름으로 찾습니다. 사번으로 찾으려면 한 열을 지정" |
| 리듀서 시험은 화면이 이벤트를 **안 보내도** 통과 / 단건 다중 절단 회귀 시험 없음 | 모달의 상태·동작 전부를 `useWageBulkUpdate` 훅으로 떼고, **가짜 브리지로 훅을 화면처럼 모는 jsdom 시험**(머리글 응답을 시험이 원할 때 도착시킴). 겹친 이력 2줄·같은 날짜 덮어쓰기 시험 추가 |
| 날짜 박힌 조사 보고서가 `docs/`에 들어감(문서 보존 규칙 위반) | `artifacts/reviews/`로 이동, README·지도에 위치 명시 |

**시험 하네스**: 모달의 동작은 `useWageBulkUpdate.test.tsx`(jsdom, 가짜 브리지)로, 실제 화면은 `artifacts/scripts/capture-wage-bulk-modal.cjs`(빌드본 구동, 7장 + 화면에서 읽은 값 JSON)로 본다. 화면 컴포넌트 전체를 렌더하는 시험은 여전히 없다.
