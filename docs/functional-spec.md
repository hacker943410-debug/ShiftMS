# 기능 명세서

## 문서 역할
- 이 문서는 `교대근무관리시스템 v0.4.5`의 현재 기능 범위와 화면별 동작을 한 번에 확인하는 제품 기능 기준서다.
- 운영 절차는 `docs/operator-quick-start.md`, 운영 기준 데이터는 `docs/operations-reference.md`, 릴리즈 판단은 `artifacts/releases/v0.4.5/RESULT_REPORT.md`를 기준으로 본다.
- 버전별 변경 이력은 `docs/patch-notes.md`를 기준으로 본다.

## 1. 제품 개요
- 제품명: `교대근무관리시스템 v0.4.5`
- 형태: Windows 중심 로컬 데스크톱 앱
- 기술 스택: Electron + React + TypeScript + Vite + SQLite
- 목적: 교대근무 기준정보 관리, 근무표 배포, 실적 승인, 수당 반영, 품의 문서 출력을 하나의 앱에서 처리한다.

## 2. 사용자와 권한
- 관리자: 운영 관리, 접근 이력, 사용자 관리, DB업데이트를 포함한 전체 기능 사용
- 계획 담당: 직원/근무지/교대 패턴/월간 스케줄 기준정보 수정과 배포 수행
- 승인 담당: 실적 승인/재승인, 수당 검토/승인 수행
- 사용자: 일상 운영 기준의 조회와 일반 화면 접근
- 모든 역할은 앱 재시작 시 다시 로그인해야 하며, 신규 계정은 첫 로그인 시 비밀번호 변경을 먼저 완료해야 한다.

## 3. 메뉴 구성

2. 인력 관리
3. 근무지 관리
4. 근무표 배포

## 4. 공통 동작 원칙
1. renderer는 UI와 사용자 입력만 담당한다.
2. 파일 시스템 접근, 폴더 감시, Excel 입출력, SQLite 저장은 Electron main/preload를 통해서만 처리한다.
3. 승인 결과와 수당 결과는 이력 기반으로 저장하며 조용한 덮어쓰기를 금지한다.
4. 수당 계산은 승인 당시 저장한 실적 스냅샷만 기준으로 재현한다.
5. 재승인 시 최신 승인 이력이 현재 기준이 되고, 수당 이력도 함께 최신 승인 기준으로 갱신된다.
6. 수당 결과는 `검토대기 -> 승인/반려 -> 품의승인` 흐름으로 관리하며, 최종 업무 마감은 `품의 승인`에서 처리한다.
7. 품의서/별첨 출력은 `승인` 또는 `품의승인` 상태 수당만 대상으로 수행한다.
8. 앱 업데이트 안내와 패치노트는 내부 모달로 제공하며, 설치 적용 전 DB 백업이 필요한 버전은 백업 성공 후에만 재시작 적용을 진행한다.

## 5. 화면별 기능 명세

### 5.1 대시보드
- 승인 대기 현황, 수당 집계, 주요 운영 지표를 보여준다.
- 운영자는 첫 화면에서 현재 처리해야 할 항목 수를 확인한다.
- 조회 방식은 `연도/월 기준`과 `기간 직접 지정`을 지원하며, 기간 직접 지정에서는 `YYYY-MM ~ YYYY-MM` 범위로 지표와 내보내기 기준을 맞춘다.
- `기간 직접 지정`의 `시작 월`, `종료 월`은 앱 공통 날짜 선택 팝오버와 같은 톤의 월 선택 UI를 사용한다.

### 5.2 인력 관리
- 인력 기본정보를 등록, 수정, 조회한다.
- 인력의 근무지 배정, 시급, 상태를 관리한다.
- Excel Import 기반 `시급 일괄 업데이트` 기능을 지원한다.
- 사용자는 근무지명/이름/시급 컬럼 매핑, 적용일, 적용 전/후 미리보기를 확인한 뒤 일괄 반영할 수 있다.
- 인력 이력은 이후 실적 승인과 수당 계산의 기준 데이터로 사용된다.
- 등록/수정/시급 변경은 `계획 담당` 또는 `관리자` 권한이 필요하다.

### 5.3 근무지 관리
- 1단계: 근무지 패턴과 조 구조를 등록한다.
- 2단계: 인력을 조에 배치하고 조별 정원을 관리한다.
- Excel Import 기반 `패턴 적용된 근무지 추가` 기능을 지원한다.
- 표준 템플릿 근무표를 분석해 Cycle, 조별 offset, 정원 제안을 산출하고 근무지 등록 1단계 draft에 자동 반영한다.
- 패턴 분석 결과는 `분석 결과`, `그룹별 상세`, `불일치 내역`, `원본 데이터` 탭으로 미리볼 수 있다.
- 드래그 앤 드롭으로 인력을 조 간 이동할 수 있어야 한다.
- 조 표기는 `A조`, `B조`처럼 정규화한다.
- DB업데이트로 들어온 `A`, `B`, `C` 같은 조명도 자동으로 `A조`, `B조`, `C조`로 매핑한다.
- 근무지 등록 시 운영 관리에서 등록한 `사이트 명` 선택값을 지정할 수 있으며, 품의서 출력의 사이트/근무지 구분에 사용한다.
- 저장/완료/footer action은 `계획 담당` 또는 `관리자` 권한이 필요하다.

### 5.4 근무표 배포
- 대상 월, 근무지, 승인된 양식을 선택해 근무표를 생성한다.
- 배포 결과는 저장 경로와 이력 기준으로 다시 확인할 수 있다.
- 승인된 양식 버전만 실제 배포에 사용한다.
- 배포 action은 `계획 담당` 또는 `관리자` 권한이 필요하다.

### 5.5 실적 관리
- 승인 대기 폴더의 실적 파일을 읽어 행 단위 승인 상태를 보여준다.
- 각 행은 `승인`, `재승인 대기`, `재승인 완료` 흐름을 가진다.
- 최초 승인 시 승인 이력을 저장하고, 파일 전체가 완료되면 승인 완료 폴더로 이동 보관한다.
- `승인완료` 조회는 실제 승인 완료 폴더의 보관본만 보여 주고, 재승인 진행 중 최신 pending 파일은 섞지 않는다.
- 수당 관리에서 `근무지 반려`가 실행되면 해당 승인 완료 파일은 승인 대기 폴더로 다시 이동해 재승인 대상으로 올린다.
- 승인완료 폴더의 해당 실적 파일이 이미 없더라도 사용자 확인 후 근무지 반려 프로세스를 계속 진행할 수 있다.
- 이미 `품의승인`으로 마감된 수당 행이 포함된 근무지는 `근무지 반려` 자체를 차단한다.
- 승인 대기 목록은 승인 대기 폴더에 실제로 존재하는 최신 파일 기준으로 다시 읽는다.
- 재승인 시 승인 이력은 새로 추가되고, 최신 승인 내용이 현재 기준이 된다.
- 재승인 확정은 현재 파일의 `변경 가능` 행이 모두 현재 사이클 기준으로 다시 승인된 경우에만 허용한다.
- 임의 시급 지정이 필요한 경우 기본은 재승인 시점에만 적용하고 승인 이력 비고에 남긴다.
- 임의 시급 적용 시 사용자가 동의하면 현재 직원 시급정보도 클릭 시점의 기준일로 함께 갱신한다.
- 승인/재승인/확정 action은 `승인 담당` 또는 `관리자` 권한이 필요하다.

### 5.6 수당 관리
- 승인된 최신 실적을 기준으로 수당 현황과 이력을 조회한다.
- 승인 시점에 수당 결과가 즉시 생성되어야 하며, 별도 `미산출 일괄 계산` 흐름은 사용하지 않는다.
- `수당 산출 현황` 탭에서는 최신 승인 기준 수당 결과를 조회하고, 행별 `승인`과 근무지별 `근무지 승인 / 근무지 반려`를 처리한다.
- 수당 결과의 기본 상태는 `검토대기`이며, 운영자는 `승인` 또는 `반려`로 상태를 전환할 수 있다.
- `근무지 반려`를 실행하면 반려 사유 입력이 필수이며, 해당 근무지의 `검토대기`와 `승인` 상태 수당을 모두 `반려`로 전환하고 연결된 승인 완료 실적 파일을 승인 대기 폴더로 되돌린다.
- `품의승인` 상태 수당이 포함된 근무지는 최종 마감 건이 섞인 상태이므로 `근무지 반려`를 실행할 수 없다.
- `품의승인` 상태 수당은 재승인 화면과 승인완료 목록에서도 `변경불가` 항목으로 표시한다.
- `품의 승인`은 승인된 수당만 묶어 PDF 출력 기준 미리보기를 확인한 뒤 최종 마감하는 단계다.
- 품의 승인 완료 시 문서 출력, 자동 백업, 승인 이력 저장이 함께 수행되며 SQLite 기준 `품의 승인 기록 저장 + 수당 상태 proposal-approved 전환`은 하나의 트랜잭션으로 반영한다.
- `품의 이력` 탭에서는 최신 수당 상태 이력과 최종 품의 승인 기록을 함께 조회한다.
- 재승인 시 최신 승인 기준의 수당 금액, 근무 시간, 적용 시급이 현재 이력에 반영되어야 한다.
- 선지급 대상은 선지급 날짜를 별도로 저장하고 일반 지급 합계와 분리해 관리한다.
- PDF, Excel 출력은 품의서/별첨 문서 생성 기능으로 제공하며 승인된 수당만 출력한다.
- 수정 품의서 Excel 양식은 고객사명이 있으면 `B:C`에 고객사명, `D`에 근무지명을 쓰고 같은 고객사가 연속되면 `B:C`를 세로 병합한다.
- 고객사명이 없는 근무지는 해당 행의 `B:D`를 병합해 근무지명을 표시하며, 근무지 수에 따라 일반 지급/선지급/푸터 행 위치를 동적으로 이동한다.
- 문서 출력은 필요할 때 다시 수행하며, 기존 출력 이력은 참고 정보로 유지한다.
- 승인/반려/품의 승인 action은 `승인 담당` 또는 `관리자` 권한이 필요하다.

### 5.7 활동 이력
- 로그인, 화면 이동, 승인, 반려, 품의 승인 같은 주요 운영 행위를 조회한다.
- 액션 유형, 사용자, 기간 기준으로 필터링해 감사 추적에 사용한다.
- 메뉴 자체는 `관리자` 권한에서만 보인다.

### 5.8 운영 관리
- 경로 설정: 승인 대기, 승인 완료, 근무표 출력, 품의서/별첨 출력, 복원 파일 경로 저장
- DB 자동/수동 백업: 현재 SQLite 운영 DB를 JSON과 Excel `.xlsx` 형식으로 저장하고, Access 원본 경로가 확인되면 `.accdb` 사본도 함께 보관
- 공휴일 관리: 연도별 공휴일 저장/수정/삭제
- 요율 관리: 연도별 수당 요율 버전 관리
- 사용자 관리: 계정 생성, 수정, 삭제
- 사이트 명 관리: 근무지 등록 시 사용할 사이트 명 선택값 등록, 수정, 삭제
- 양식 관리: 양식 등록, 검토, 승인, 기본 사용 전환
- DB업데이트: JSON 백업 또는 Access DB 기준으로 운영 데이터 복원
- 메뉴 자체는 `관리자` 권한에서만 보인다.

## 6. 핵심 데이터 흐름

### 6.1 근무표 -> 실적
1. 월간 근무표를 생성/배포한다.
2. 반납된 실적 파일을 승인 대기 폴더에서 읽는다.
3. 실적 파일의 각 행을 승인 또는 재승인한다.

### 6.2 실적 승인 -> 수당 반영
1. 실적 행 승인 시 승인 스냅샷을 저장한다.
2. 같은 시점에 수당 계산을 즉시 수행한다.
3. 계산 결과는 `검토대기` 상태의 수당 결과로 저장된다.
4. 운영자는 수당 관리에서 수당을 `승인 / 반려` 처리한다.
5. `근무지 반려`를 실행하면 해당 근무지 실적 파일은 승인 대기 폴더로 돌아가고, 실적 관리에서는 재승인 대상으로 다시 검토한다.
6. 단, `품의승인` 상태 수당이 포함된 근무지는 근무지 반려를 실행할 수 없다.
7. 승인완료 폴더에 해당 실적 파일이 없으면 확인 메시지를 띄우고, 동의 시 수당 반려와 재승인 표시를 계속 진행한다.
8. 문서 출력은 승인된 수당만 대상으로 별도 단계에서 실행한다.

### 6.3 재승인 -> 수당 갱신
1. 재승인 대상 행을 현재 파일 기준으로 비교한다.
2. 이미 `품의승인`된 행은 `변경불가`로 고정하고 비교/재승인 대상에서 제외한다.
3. 재승인 완료 시 새 승인 이력을 저장한다.
4. 파일 최종 반영은 현재 파일의 변경 가능 행이 모두 재승인 완료된 뒤에만 허용한다.
5. 새 계산 결과는 다시 `검토대기` 상태에서 시작한다.
6. 품의 승인 완료 전이면 수당 승인/반려를 다시 수행할 수 있다.
7. 출력이 필요하면 최신 승인 결과 기준으로 문서를 다시 출력한다.

## 7. 운영 규칙
1. Pool 근무자의 대체근무는 기록에는 남기되 실적 관리 화면과 수당 계산 대상에서는 제외한다.
2. 퇴직자 선지급 건은 일반 지급 합계와 품의서 2번 항목에서 제외하고 별도 항목으로 관리한다.
3. 품의 승인 완료 전에는 수당 상태를 변경할 수 있지만, 품의 승인 후에는 같은 계산 결과를 다시 검토 상태로 되돌리지 않는다.
4. 수당 문서 출력 이력은 계산 생성 조건이 아니라 계산 결과에 대한 부가 이력이다.
5. 품의 승인 DB 반영이 실패하면 출력 문서와 자동 백업 파일은 남을 수 있으므로, 운영자는 저장 산출물 확인 후 품의 승인을 다시 시도한다.
6. 운영 DB 백업은 JSON과 Excel `.xlsx` 형식으로 함께 저장하고, Access 원본 경로가 확인되면 `.accdb` 사본도 함께 보관한다.
7. DB업데이트 복원 입력은 JSON 백업 파일과 Access DB 파일을 허용하며, Excel 파일은 복원 대상으로 선택하지 않는다.
