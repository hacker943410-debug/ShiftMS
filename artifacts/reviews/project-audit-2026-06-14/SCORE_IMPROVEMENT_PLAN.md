## 1. 가장 중요한 깨달음 — 몇 가지만 고치면 여러 항목이 한꺼번에 오릅니다

8개 항목을 따로 보면 막막하지만, 실제로는 **소수의 수정이 여러 항목을 동시에 끌어올립니다.** 아래 4가지가 "적은 비용으로 가장 크게 점수를 올리는" 핵심입니다.

| 핵심 수정 | 무슨 일인가 | 같이 오르는 항목 | 노력 |
|---|---|---|---|
| **① 되돌리기가 기록을 지우지 않게 고치기** | 백업에서 되돌릴 때 승인·감사 기록 4종이 사라지는 걸 막고, 자동 점검까지 박아둠 | 데이터안전 · 아키텍처 · 코드품질 · 테스트 · 보안 (**5개**) | 작음~중간 |
| **② 지난 날짜 수당을 그 날짜 요율로 계산** | 과거 근무를 최신 요율이 아니라 그 당시 요율로 계산하게 순서만 바로잡음 | 도메인정확성 · 아키텍처 · 코드품질 · 테스트 (**4개**) | 작음 |
| **③ 배포할 때 자동 시험을 반드시 통과하게 막기** | 시험을 안 돌리고 내보내던 걸 막고, 멈춰 있던 검사 장치를 실제로 켬 | 프로세스 · 테스트 · 아키텍처 (**3개**) | 작음~중간 |
| **④ 로그인 잠금 살리기 + '1234' 노출 제거** | 여러 번 틀리면 잠기게 하고, 화면에 적힌 관리자 비번 '1234'를 지움 | 보안 (거의 다 만들어져 있어 잇기만 하면 됨) | 작음 |

이 4가지는 모두 **"이미 승인된 자료가 다시 승인 대상이 되는 대량 재승인 사고" 위험이 없습니다.** 파일·승인을 알아보는 핵심 규칙을 건드리지 않기 때문입니다. 이것만 해도 종합이 약 **6.3점(C+)** 으로 오릅니다.

> ⚠️ **묶음 배포 주의:** ①번(되돌리기 수정)은 반드시 "근무표 복구 · 옛 기록 정리"와 **한 묶음으로 함께** 내보내야 합니다. 일부만 내보내면 이미 승인된 모든 파일이 다시 승인 대기로 보이는 사고가 날 수 있습니다.

## 2. 항목별 상세 방안

각 항목은 **우선순위 순**으로 정리했습니다. 노력 크기는 작음 / 중간 / 큼으로, 효과는 올라가는 점수로 표시했습니다.

### 2-1. 데이터 안전 (지금 3.5점 → 전부 하면 7.5점) — **가장 낮고, 가장 급함**

**왜 낮은가:** 백업에서 되돌릴 때 "누가 어떤 수당을 승인했는지"에 대한 결재 기록과 로그인·접근 기록이 소리 없이 사라집니다. 백업 안에는 그 기록이 분명히 들어 있는데 되돌릴 때 빈 채로 덮어씁니다. 더 나쁜 건, 되돌린 직후 이전 자료를 바로 영구 삭제해서 되살릴 수도 없다는 점입니다. 이걸 잡아낼 자동 점검도 하나 없습니다.

**무엇을 하면 되나:**

1. **되돌릴 때 모든 기록을 빠짐없이 되살리기** — 정해둔 목록만 채우는 방식을 버리고 백업 안의 모든 표를 그대로 되살립니다. (효과 **+1.6점, 가장 큼** · 노력 작음 · 재승인 위험 없음)
2. **되돌린 직후 이전 자료를 바로 지우지 말고 며칠 보관** — 문제가 생겨도 되살릴 마지막 기회를 남깁니다. 며칠 뒤 자동 정리. (효과 +0.5점 · 노력 작음 · 위험 없음)
3. **되돌려도 기록이 살아있는지 자동으로 점검** — 4종 기록을 넣고 되돌린 뒤 그대로인지 확인하는 검사를 붙여, 앞으로 같은 사고를 출시 전에 막습니다. (효과 +0.6점 · 노력 작음 · 위험 없음)
4. **잘못 연결·짝 잃은 기록을 데이터베이스가 직접 거부** — 자료 간 연결 규칙을 프로그램이 아니라 저장소가 강제로 지키게 합니다. (효과 +0.7점 · 노력 큼 · 도입 전 기존 자료 점검 필요)
5. **수당 승인을 한 번에 통째로 저장** — 승인 기록과 계산 결과를 한 묶음으로 저장해, 도중에 꺼져도 찌꺼기 기록이 안 남게 합니다. (효과 +0.4점 · 노력 중간 · 위험 낮음)
6. **사용 중 사본이 항상 하나만 되게 저장소가 보장** (효과 +0.2점 · 노력 작음 · 다지기 성격)

> 이 항목은 급여 정확성과 직결돼 종합 점수에 **1.5배**로 반영됩니다. 작은 수정으로도 전체 등급을 가장 크게 끌어올리는 지렛대입니다. 비용 적은 1~3번만 해도 6.0점.

### 2-2. 프로세스 / 배포 절차 (지금 3.8점 → 전부 하면 7.0점)

**왜 낮은가:** 내보내기(배포) 단추를 눌러도 계산이 맞는지 자동 시험이 한 번도 안 돕니다. 만들어 둔 검사 장치마저 돌릴 컴퓨터가 연결 안 돼 "대기 중"에 멈춰 있어, 검사한 적 없이 배포가 나갔습니다. 다른 사람이 코드를 한 번 더 본 흔적도 없고, 작업하던 가지에서 곧바로 출시본을 떼어 냅니다. 설치 파일엔 "만든 사람 확인 도장"도 없습니다.

**무엇을 하면 되나:**

1. **시험이 통과해야만 내보내지도록 묶기** — 자동 시험이 하나라도 실패하면 배포가 멈추게 합니다. 잘못된 급여 계산이 그대로 새 나가던 가장 큰 구멍을 막습니다. (효과 **+1.0점, 가장 큼** · 노력 작음 · 위험 없음)
2. **검사 컴퓨터를 실제로 연결(또는 클라우드 검사로 전환)** — 멈춰 있던 검사가 코드를 올릴 때마다 진짜로 돌게 합니다. (효과 +0.7점 · 노력 중간 · 위험 없음)
3. **검사 통과 없이는 합치거나 내보낼 수 없게 잠그고, 출시는 검토용 가지에서 떼기** — "다른 점검 없이 바로 출시"하던 관행을 끊습니다. (효과 +0.9점 · 노력 중간 · 위험 없음)
4. **설치 파일에 만든 사람 확인 도장 넣기(코드 서명)** — 사용자 PC 경고를 줄이고 위·변조 확인이 가능해집니다. (효과 +0.5점 · 노력 중간 · 인증서 구매 필요)
5. **버전마다 사람이 확인한 점검 기록 남기기** — 이전 버전엔 있던 체크리스트·점검 보고를 되살립니다. (효과 +0.3점 · 노력 작음)

> 좋은 재료(검사 장치, 점검 도구)는 이미 만들어져 있고 **배포 단추에 연결만 안 돼 있습니다.** 1~3번이 핵심.

### 2-3. 도메인 정확성 / 급여 계산 (지금 4.5점 → 전부 하면 7.5점)

**왜 낮은가:** 계산기 자체(분·시간·반올림)는 정확합니다. 점수를 끌어내리는 건 사실상 한 가지 — 과거 날짜로 들어온 근무의 수당이 "그 날짜 요율"이 아니라 "가장 최근 요율"로 계산될 수 있다는 점입니다. 옛 요율과 새 요율이 동시에 켜진 기간엔 실제로 잘못 지급될 수 있습니다.

**무엇을 하면 되나:**

1. **과거 날짜 건을 그 날짜 요율로 계산하게 순서 바로잡기** — 이미 다른 보강 경로는 올바르게(날짜 기준) 하고 있으니 똑같이 맞춥니다. (효과 **+0.9점, 가장 큼** · 노력 작음 · 재승인 위험 낮음 — 요율 종류를 행마다 따로 저장해 둬서 기존 승인은 그대로)
2. **그 수정이 맞게 도는지 검증 시험 추가** (효과 +0.3점 · 노력 작음 · 위험 없음)
3. **근무 구분(주간·오후·야간·비번)을 정해진 4가지로만 받게 잠그기** — 실수로 잘못된 값이 흘러드는 걸 미리 막습니다. (효과 +0.4점 · 노력 중간)
4. **휴일 대체근무 보조 경로의 "항상 빈손" 문제 해결** — 누락되던 휴일 대체 건 일부를 제대로 잡습니다. (효과 +0.3점 · 노력 중간 · **재승인 위험 있어 신중히** — 안 보이던 행이 새로 보일 수 있음)
5. **한 줄이라도 0분이면 더 일찍 막기** (효과 +0.2점 · 노력 작음)

> 1번 작은 수정만으로 가장 큰 효과를 봅니다.

### 2-4. 테스트 / 자동 점검 (지금 4.5점 → 전부 하면 7.5점)

**왜 낮은가:** 시험의 양은 많고 실제 데이터로 끝까지 돌려보는 부분은 훌륭하지만, 정작 가장 위험한 두 곳이 비어 있습니다 — ①되돌리기로 기록이 사라지는 사고, ②지난 근무에 요율을 잘못 붙이는 문제를 잡는 시험이 없습니다. 게다가 배포할 때 시험이 한 번도 안 돌고, 검사 장치도 꺼져 있어 시험이 문지기 역할을 못 합니다.

**무엇을 하면 되나:**

1. **되돌리기가 기록을 지우는지 잡는 시험 추가** — 지금은 일부러 "실패"로 두어 문제를 증명하고, 고치면 자동으로 "통과"로 바뀌어 재발을 막습니다. (효과 **+0.9점, 가장 큼** · 노력 작음 · 위험 없음)
2. **시험을 통과해야만 내보내지게 막기** — 위 시험을 포함한 모든 시험이 출시 전에 강제로 돕니다. (효과 +0.7점 · 노력 작음 · 위험 없음)
3. **지난 날짜에 옛 요율이 제대로 붙는지 전체 흐름으로 시험** (효과 +0.6점 · 노력 중간 · 위험 없음)
4. **검사 장치를 실제로 켜서 항상 돌게** (효과 +0.4점 · 노력 중간)
5. **급여 반올림의 까다로운 경계값까지 시험 보강** — 드문 금액에서 1원 어긋남을 막습니다. (효과 +0.3점 · 노력 작음)

> 시험은 전부 "추가만" 하는 것이라 재승인 위험이 전혀 없습니다.

### 2-5. 코드 품질 (지금 5.2점 → 전부 하면 7.5점)

**왜 낮은가:** 기계적으로는 깔끔하지만, 코드의 실수(처리하다 만 작업·죽은 코드·위험한 임시 처리)를 자동으로 잡아주는 검사 도구가 아예 없습니다. 또 지난번에 가장 위험하다고 짚은 두 결함(되돌리기 기록 삭제, 요율 잘못 붙기)이 그대로 남아 점수를 누르고 있습니다.

**무엇을 하면 되나:**

1. **되돌리기로 승인 기록이 사라지는 문제 막기** (효과 +0.6점 · 노력 중간 — 데이터 안전 ①과 같은 수정)
2. **코드 자동 점검 도구 도입** — 사람이 일일이 안 봐도 실수를 컴퓨터가 찾아내 경고합니다. 이 항목에서 효과가 가장 큰 한 방. (효과 **+0.8점** · 노력 중간 · 위험 없음)
3. **지난 날짜 근무의 요율을 그 당시 기준으로** (효과 +0.5점 · 노력 중간 — 도메인 ①과 같은 수정)
4. **관리자 '1234' 끊기 + 군더더기 0.25초 지연·죽은 코드 정리** — 보안·속도·깔끔함이 한 번에 좋아집니다. (효과 +0.3점 · 노력 작음)
5. **근무 구분 값을 정해진 4가지로 잠그기** (효과 +0.3점 · 노력 큼)
6. **거대 파일을 안전하게 조금씩 쪼개기** — 동작은 그대로, 고치기 쉽게만. (효과 +0.2점 · 노력 큼)

### 2-6. 보안 (지금 5.2점 → 전부 하면 8.0점)

**왜 낮은가:** 보안 뼈대(화면·기능 사이 벽, 비밀번호 보관, 권한 확인)는 튼튼합니다. 문제는 "정문"인 로그인 — 관리자 첫 비번 '1234'가 화면에 그대로 적혀 있고, 비밀번호를 여러 번 틀려도 잠그는 기능이 만들다 만 채 안 돕니다. 자동 업데이트 파일엔 정품 도장이 없고, 되돌리기 때 감사 기록이 사라집니다.

**무엇을 하면 되나:**

1. **여러 번 틀리면 계정 잠기게 만들기** — 무한정 번호를 찍어보는 공격을 막습니다. 거의 다 만들어져 있어 마지막 연결만 이으면 됩니다. (효과 **+0.7점, 가장 큼** · 노력 작음 · 위험 없음)
2. **관리자 '1234' 화면 노출 끊기** — 추측 공격의 출발선을 없앱니다. (효과 +0.4점 · 노력 작음 · 화면 문구 제거는 즉시, 비번 무작위화는 별도 안내와 함께)
3. **자동 업데이트 설치 파일에 정품 도장(서명) 넣기** (효과 +0.6점 · 노력 큼 · 인증서 필요)
4. **되돌리기 때 사라지는 승인·접속 기록 살리기** (효과 +0.5점 · 노력 중간 — 데이터 안전 ①과 같은 수정)
5. **화면 외부 차단 울타리 추가** — 빠진 표준 안전장치 하나 채우기. (효과 +0.2점 · 노력 작음)

> 1·2·5번은 비용이 작아 빠르게 올릴 수 있습니다.
