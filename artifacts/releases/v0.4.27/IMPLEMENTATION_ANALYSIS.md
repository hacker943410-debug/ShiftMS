# Implementation Analysis

## Cause
- 실적 엔트리에는 `sortOrder`만 있고 조 정보가 없어 화면이 근무지 단위로만 묶였다.
- 반려 상태의 승인대기 파일도 파일 크기와 수정 시간이 같으면 DB의 기존 분석 결과를 재사용했다.
- 기존 `None` 취소는 원근무자 셀 또는 같은 슬롯 변경 후 셀만 보았고, 변경/대체 표의 `원근무자 -> None`과 법정휴일 행을 연결하지 않았다.
- 로그인 실패 누적은 운영 감사보다 계정 잠금 해제 부담을 크게 만들었다.

## Approach
- `PerformanceEntryRecord`와 `performance_entries`에 `teamLabel/team_label`을 추가했다.
- 파서가 월근무표 저장본과 인력 배치 이력에서 조 정보를 해석해 실적 행에 싣도록 했다.
- 실적관리 정렬과 화면 렌더링은 조 그룹을 먼저 만들고 기존 행 액션을 유지했다.
- `pending + rejected` 파일은 캐시 재사용 대상에서 제외했다.
- 변경/대체 표의 `None` 취소 맵을 만들고 법정휴일 파싱 전에 원근무자 취소 여부를 확인했다.
- 로그인 잠금 판정과 잠금 안내를 제거하고 실패 횟수 기록은 유지했다.
