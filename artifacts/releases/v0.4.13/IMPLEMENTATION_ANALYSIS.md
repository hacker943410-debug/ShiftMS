# v0.4.13 구현 분석

## 문제 원인
- 문서 출력 경로가 템플릿/문서 종류별로 다르게 해석되어 사용자가 지정한 폴더와 실제 저장 위치가 어긋날 수 있었다.
- 별첨1은 기본근로 라인을 우선 선택하는 fallback 때문에 연장근무 단독 행이 의도와 다르게 표시될 수 있었다.
- 문서 표시 금액과 최종품의수당 계산의 반올림 계층이 명확히 분리되어 있지 않았다.
- DB복원 시 상태 원천값이 공백/미분류인 경우 그대로 미분류로 남아 운영 필터와 맞지 않았다.
- 품의서 문서번호는 문서일자 월이 아니라 기존 집행월 값을 사용하고 있었다.

## 해결 방향
- 문서 출력 경로 계산을 전용 helper로 분리하고 모든 문서 종류가 같은 규칙을 사용하도록 했다.
- 문서 출력 금액은 `roundUpWon` helper를 통해 최종 반영 계층에서만 원 단위 올림을 적용한다.
- 별첨1 행 생성 시 기본근로 fallback을 제거하고, 필수 셀 검증으로 빈칸 출력을 방지한다.
- DB복원 상태 normalization을 명시 함수로 분리해 Access/JSON 복원 경로에서 재사용한다.
- 품의서 문서번호 산출 helper를 shared domain에 두고 Excel/PDF가 같은 기준을 사용하도록 했다.
