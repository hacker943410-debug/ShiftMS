# v0.4.2 기능 명세

## 릴리즈 목적
- 근무지 패턴 수정 시 사용자가 입력한 cycle 원문 패턴 문자열이 저장 후에도 그대로 유지되도록 보강한다.
- 해당 hotfix를 포함한 `0.4.2` 설치본을 배포 가능 상태로 패키징한다.

## 사용자 관점 변경

### 1. 근무지 패턴 수정
- 사용자가 cycle 패턴을 수정하고 저장하면, 다시 상세/수정 화면을 열었을 때 입력한 원문 표현이 그대로 보여야 한다.
- `steps` 기준 재구성 문자열만 보이는 기존 동작은 fallback 용도로만 남는다.

### 2. 기존 패턴 데이터
- 기존 DB에 저장된 cycle 데이터는 `pattern_string`이 없을 수 있다.
- 이 경우에는 기존처럼 재구성 문자열을 보여주고, 사용자가 한 번 수정 후 저장하면 이후부터 원문 문자열을 유지한다.

### 3. 패키징 산출물
- 운영자는 `ShiftMgmt-Setup-0.4.2-x64.exe` 설치본과 `ShiftMgmt.exe` unpacked 실행 파일을 사용할 수 있다.

## 비기능 요구
- 기존 근무 패턴 계산 로직은 깨지지 않아야 한다.
- 기존 DB를 즉시 폐기하지 않고 컬럼 추가 수준으로 호환되어야 한다.
- 저장/조회 회귀는 테스트로 고정되어야 한다.

## 수용 기준
- cycle 패턴을 새 문자열로 수정 후 저장하면 재진입 시 같은 문자열이 보인다.
- 저장소 테스트와 selector 테스트가 통과한다.
- `npm run release:package`가 성공하고 설치본이 생성된다.
