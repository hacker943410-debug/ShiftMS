# V0.2.0 구현 분석

## 1. 분석 대상
- 기능 1: 인력 관리 `시급 업데이트 일괄 적용`
- 기능 2: 근무지 관리 `패턴 산출 및 적용`
- 외부 참조: `C:\Projects\Tools\패턴추출기\패턴추출기.md`

## 2. 현재 구조 분석

### 2.1 인력 관리
- 현재 [WorkforceManagementScreen.tsx](../../../src/renderer/screens/WorkforceManagementScreen.tsx)는 개별 인력의 시급 변경만 지원한다.
- 시급 이력 저장은 [employee-history-service.ts](../../../src/main/services/employee-history-service.ts)가 담당한다.
- 저장 구조는 기존 `wage_rates` 이력 테이블을 사용하며, `effective_from`, `effective_to`, `reason`을 이미 지원한다.
- 따라서 `시급 일괄 적용`은 새 테이블 없이 기존 시급 이력 구조를 재사용하는 편이 안전하다.

### 2.2 근무지 관리
- 현재 [SiteManagementScreen.tsx](../../../src/renderer/screens/SiteManagementScreen.tsx)는 1단계 패턴 등록, 2단계 조 배정 흐름을 이미 갖고 있다.
- 패턴 저장은 [shift-pattern-storage-service.ts](../../../src/main/services/shift-pattern-storage-service.ts)가 담당한다.
- 현재 draft 구조에는 `teamCount`, `cycleCount`, `cycles`, `teamCycleAssignments`, `teamCapacities`가 있어, 외부 패턴 산출 결과를 임시 draft로 주입하기에 적합하다.
- 즉, 패턴 산출 기능은 DB에 바로 저장하지 않고 `근무지 등록 1단계 draft 자동 채우기` 방식으로 연결하는 것이 현재 구조와 가장 잘 맞는다.

### 2.3 파일 선택 / Excel 처리
- 현재 Electron main에는 파일 선택 다이얼로그 구현이 있고, Excel 관련 런타임 의존성으로 `exceljs`가 이미 포함돼 있다.
- 따라서 두 기능 모두 새 의존성 없이 `exceljs + 기존 IPC 패턴`으로 구현 가능하다.
- 파일 시스템 접근은 renderer가 직접 하지 않고 `main -> preload -> renderer` 흐름으로만 노출해야 한다.

## 3. 기능 1 구현 방향

### 3.1 사용자 흐름
1. 인력 관리 상단 액션에 `시급 일괄 업데이트` 버튼 추가
2. 버튼 클릭 시 신규 모달 열기
3. 모달에서 Excel 파일 선택
4. `가이드 보기` 버튼으로 설명 모달 열기
5. 컬럼 매핑 입력
   - 근무지명 열
   - 이름 열
   - 시급 열
6. 적용일 선택
7. `미리보기` 실행
8. 적용 전 / 적용 후 비교 확인
9. `시급 일괄 업데이트` 실행

### 3.2 매칭 규칙
- V0.2.0에서는 `근무지명 + 이름` 조합으로 인력을 찾는다.
- 기준 데이터는 현재 앱에 저장된 인력의 최신 활성 배정 기준이다.
- 아래 항목은 미리보기에서 `적용 제외`로 표기한다.
  - 근무지명 불일치
  - 동일 근무지 내 이름 중복
  - 시급 값 숫자 변환 실패
  - 빈 행
  - 적용일이 현재 활성 시급 시작일보다 빠르거나 같은 경우
  - 현재 시급과 동일 금액인 경우

### 3.3 저장 방식
- 실제 저장은 기존 `wage_rates` 이력 구조를 그대로 사용한다.
- 각 대상 행에 대해 새 시급 레코드를 추가하고, 기존 활성 시급의 종료일은 적용일 전날로 자동 닫는다.
- `reason`에는 최소한 아래 정보를 남긴다.
  - `시급 일괄 업데이트`
  - 원본 파일명
- 이 방식은 추후 이력 조회와 재현성 측면에서 유리하다.

### 3.4 미리보기 출력
- 미리보기는 최소 아래 컬럼을 가진다.
  - 근무지명
  - 이름
  - 현재 시급
  - 변경 시급
  - 차이
  - 적용일
  - 상태
  - 제외 사유
- 적용 가능한 행 수, 제외 행 수, 동일 금액 행 수 요약 카드도 함께 제공한다.

### 3.5 가이드 모달
- 운영자가 컬럼 매핑을 이해하기 쉽도록 예시 표 형태의 시각 안내를 제공한다.
- 실제 이미지 파일 대신 renderer에서 재사용 가능한 안내 도식 컴포넌트 또는 inline SVG를 사용하면 의존성 증가 없이 유지보수하기 쉽다.
- 가이드에는 아래 내용을 포함한다.
  - Excel 예시 표
  - 컬럼 매핑 입력 방법
  - 숫자 시급 형식 예시
  - 미리보기 후 적용해야 한다는 주의 문구

## 4. 기능 2 구현 방향

### 4.1 사용자 흐름
1. 근무지 관리 목록 화면 또는 1단계 상단 액션에 `근무표 파일로 패턴 산출` 버튼 추가
2. 버튼 클릭 시 신규 모달 열기
3. 모달에서 Excel 파일 선택
4. `가이드 보기` 버튼으로 표준 템플릿 규격 안내 확인
5. 분석 실행
6. 분석 결과 미리보기 확인
7. `근무지 등록(1단계 이동)` 클릭
8. Site draft에 산출 결과를 자동 반영
9. 사용자가 근무지명, 근무시간, Pool 여부 등을 검토 후 저장

### 4.2 외부 문서 적용 범위
- 외부 문서의 핵심 로직은 아래 3단계다.
  1. 엑셀 파싱
  2. 패턴 탐지
  3. 그룹 분류
- V0.2.0에서는 해당 로직을 `표준 템플릿 형식` 분석 기능으로 구현한다.
- 문서의 향후 확장 항목 중 아래 항목은 이번 범위에서 제외한다.
  - 빈 템플릿 생성
  - 다양한 원본 레이아웃 직접 파싱
  - 주말 / 공휴일 변형 규칙 자동 학습
  - 결과 파일 내보내기

### 4.3 분석 결과를 현재 패턴 구조로 변환하는 방식
- 외부 문서의 `그룹`은 현재 앱의 `Cycle`로 변환한다.
- 외부 문서의 `offset`은 현재 앱의 `teamIndexes`로 변환한다.
- 팀은 `근무자 1명 = 팀 1개`가 아니라 `같은 그룹 + 같은 offset` 조합 단위로 만든다.
- 이유:
  - 같은 패턴 그룹 안에서 같은 offset을 공유하는 근무자들은 같은 조 회전 위치를 의미한다.
  - 현재 앱의 `teamCapacities`는 조 정원 수를 표현할 수 있으므로, 해당 조의 인원 수를 정원으로 넣는 구조가 자연스럽다.

### 4.4 변환 규칙
- `group` 1개 -> `cycle` 1개
- `group + offset` 고유 조합 1개 -> `teamLabel` 1개
- 같은 `group + offset`에 속한 인원 수 -> `teamCapacities.maxHeadcount`
- 분석 기준 시작일 -> `patternStartDate`
- 탐지된 근무코드 사이클 -> 현재 앱의 `patternString`
- 근무시간 / 휴게시간은 외부 문서에 없으므로 현재 앱 프리셋 값으로 초기 채움 후 사용자가 저장 전 검토한다.

### 4.5 결과 미리보기
- 분석 전 파일 파싱 요약
  - 분석 기간
  - 총 일수
  - 근무자 수
  - 경고 목록
- 분석 후 그룹 요약
  - Cycle 수
  - 예상 조 수
  - Cycle별 패턴 문자열
  - offset별 조 구성
  - 조별 예상 정원
  - 불일치 / 신뢰도
- `근무지 등록(1단계 이동)` 버튼을 누르면 DB 저장 없이 draft만 이동한다.

### 4.6 가이드 모달
- 외부 문서의 표준 템플릿 형식을 시각적으로 설명한다.
- 최소 포함 항목:
  - 1행 날짜
  - 2행 요일
  - 3행 공휴일
  - 4행 이후 근무자별 근무코드
  - 한 근무자가 여러 행인 원본은 `D/N/O` 기준으로 한 행으로 병합해야 한다는 안내

## 5. 기술 설계 결론
- 두 기능 모두 새 DB 테이블 없이 기존 저장 구조 확장만으로 구현 가능하다.
- 공통적으로 필요한 기술 요소는 아래와 같다.
  - Electron `openFile` 다이얼로그
  - `exceljs` 기반 엑셀 파싱
  - main service 단의 미리보기 / 적용 로직
  - preload / bridge 계약 추가
  - renderer 모달, 가이드 모달, 미리보기 표
- 공통 설계 포인트:
  - 실제 반영 전에 미리보기 반드시 선행
  - 적용 가능한 행과 제외 행을 구분
  - 가이드와 경고를 한국어로 충분히 노출
  - renderer는 계산 / 파싱 / 매칭 로직을 직접 가지지 않음

## 7. 구현 전 확인 포인트
1. 시급 일괄 적용의 인력 식별 기준을 `근무지명 + 이름`으로 고정할지 여부
2. 패턴 산출 후 생성되는 `조 수`를 `group + offset` 기준으로 확정할지 여부
3. 패턴 산출 결과의 근무시간은 기본 프리셋으로 채우고 수동 검토하게 할지 여부
4. 가이드 모달 이미지는 외부 이미지 파일이 아니라 inline SVG / 안내 표로 구현할지 여부
