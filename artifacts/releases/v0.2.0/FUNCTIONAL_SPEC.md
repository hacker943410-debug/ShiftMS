# V0.2.0 기능명세

## 1. 패치 개요
- 버전: `V0.2.0`
- 성격: 운영 기준정보 입력 효율화 패치
- 대상 메뉴:
  - 인력 관리
  - 근무지 관리

## 2. 기능 1: 시급 업데이트 일괄 적용

### 2.1 목적
- 여러 인력의 시급을 한 번에 반영하되, 기존 시급 이력 구조를 유지하고 적용 전 미리보기로 변경 결과를 확인할 수 있게 한다.

### 2.2 진입 위치
- 메뉴: `인력 관리`
- 상단 액션 버튼: `시급 일괄 업데이트`

### 2.3 입력 항목
- Excel 파일
- 컬럼 매핑
  - 근무지명 열
  - 이름 열
  - 시급 열
- 적용일

### 2.4 가이드 보기
- `가이드 보기` 버튼을 누르면 별도 모달이 열린다.
- 가이드 모달은 아래 내용을 그림과 예시 표 중심으로 안내한다.
  - 예시 Excel 표 구조
  - 컬럼 매핑 입력 예시
  - 시급 숫자 형식 예시
  - 미리보기 확인 후 적용해야 한다는 주의사항

### 2.5 미리보기 규칙
- 사용자가 파일, 매핑, 적용일을 입력한 뒤 미리보기를 실행한다.
- 미리보기는 아래 상태를 구분한다.
  - 적용 가능
  - 동일 금액
  - 근무지 / 인력 미일치
  - 중복 매칭
  - 시급 값 오류
  - 적용일 오류
- 미리보기 표는 `적용 전 -> 적용 후`를 비교할 수 있어야 한다.

### 2.6 적용 규칙
- `시급 일괄 업데이트` 버튼 클릭 시 적용 가능 행만 저장한다.
- 기존 활성 시급은 적용일 전날로 종료된다.
- 새 시급 레코드는 이력으로 추가된다.
- 저장 사유에는 일괄 업데이트와 원본 파일명을 남긴다.
- 적용 제외 행은 저장하지 않으며 결과 요약에 포함한다.

### 2.7 출력 / 결과
- 결과 요약 모달 또는 메시지로 아래 항목을 표시한다.
  - 총 행 수
  - 적용 성공 건수
  - 제외 건수
  - 동일 금액 건수
  - 대표 경고 메시지

### 2.8 검증 기준
1. 같은 파일로 다시 미리보기를 실행해도 결과가 일관돼야 한다.
2. 적용 후 인력 상세 `현재 시급`과 `시급변경이력`이 함께 갱신돼야 한다.
3. 적용일이 현재 활성 시급보다 빠르거나 같으면 적용에서 제외돼야 한다.
4. 시급 숫자 파싱 실패 행은 저장되지 않아야 한다.

## 3. 기능 2: 패턴 산출 및 적용

### 3.1 목적
- 표준 형식의 근무표 Excel 파일에서 반복 Cycle과 조별 offset을 산출하고, 이를 `근무지 등록 1단계` draft에 자동 반영한다.

### 3.2 진입 위치
- 메뉴: `근무지 관리`
- 진입 버튼: `근무표 파일로 패턴 산출`

### 3.3 입력 파일 규격
- 표준 템플릿 기준
  - 1행: 날짜
  - 2행: 요일
  - 3행: 공휴일
  - 4행 이후: 근무자별 근무코드
- 한 근무자는 한 행만 사용한다.
- 근무코드는 공란 허용, 공란은 비교 대상에서 제외한다.

### 3.4 가이드 보기
- `가이드 보기` 버튼으로 별도 모달을 연다.
- 가이드에는 아래 내용이 포함된다.
  - 표준 템플릿 예시
  - 날짜/요일/공휴일/근무자 행 설명
  - 여러 행으로 흩어진 원본을 `D/N/O` 한 줄 형식으로 정리하는 방법
  - 분석 결과는 초안이며 저장 전 1단계에서 근무시간을 검토해야 한다는 안내

### 3.5 분석 규칙
- 파일 파싱 -> 패턴 탐지 -> 그룹 분류 순서로 진행한다.
- 그룹은 동일한 Cycle 패턴을 공유하는 집합이다.
- 같은 그룹 안에서 같은 offset을 공유하는 인원들은 같은 조 후보로 묶는다.

### 3.6 앱 draft 변환 규칙
- 그룹 1개 = Cycle 1개
- `그룹 + offset` 조합 1개 = 조 1개
- 같은 조합에 속한 인원 수 = 조 정원
- 분석 시작일 = 패턴 시작일
- 산출된 패턴 문자열 = Site 1단계의 `패턴 String`
- 근무시간 / 휴게시간은 기본 프리셋으로 입력되고, 사용자가 저장 전 검토한다.

### 3.7 미리보기 영역
- 파싱 요약
  - 분석 기간
  - 총 일수
  - 근무자 수
  - 경고 수
- Cycle 결과
  - 발견 Cycle 수
  - Cycle별 패턴 문자열
  - Cycle 길이
  - 신뢰도
- 조 구성 결과
  - 예상 조 수
  - 조별 offset
  - 조별 예상 정원
  - 포함 근무자 이름

### 3.8 적용 규칙
- `근무지 등록(1단계 이동)` 클릭 시 DB에는 저장하지 않는다.
- Site 1단계 draft만 아래 값으로 채운다.
  - teamCount
  - cycleCount
  - cycles
  - teamCycleAssignments
  - teamCapacities
  - patternStartDate
- 사용자는 1단계에서 근무지명, 운영 구조, 근무시간, Pool 설정을 검토한 뒤 저장한다.

### 3.9 예외 처리
- 파일 형식 오류
- 날짜 행 오류
- 근무자 데이터 없음
- 패턴 미발견
- 전체 미발견
- 날짜 불연속 경고
- 근무자 이름 중복 경고

### 3.10 검증 기준
1. 동일 파일 재분석 시 Cycle / offset 결과가 일관돼야 한다.
2. 분석 결과를 적용한 뒤 Site 1단계 달력 시뮬레이션이 깨지지 않아야 한다.
3. 팀 수와 정원이 `group + offset` 기준으로 계산돼야 한다.
4. DB 저장 전까지는 기존 근무지 데이터가 바뀌지 않아야 한다.

## 4. 공통 UX 규칙
1. 두 기능 모두 `파일 선택 -> 가이드 확인 -> 미리보기 -> 적용` 흐름을 유지한다.
2. 적용 버튼은 필수 입력값이 없으면 비활성화한다.
3. 경고와 제외 사유는 한국어로 구체적으로 보여준다.
4. 적용 전과 적용 후의 차이를 표 형태로 비교 가능해야 한다.
5. renderer는 파일 내용을 직접 읽지 않는다.
