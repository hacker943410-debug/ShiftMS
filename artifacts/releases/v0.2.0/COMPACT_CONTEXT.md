# V0.2.0 Compact Context

## 1. 이번 패치의 한 줄 목표
- 운영자가 Excel 파일 두 종류만으로 `시급 일괄 반영`과 `패턴 초안 생성`을 빠르게 수행하게 만든다.

## 2. 이번 패치에서 반드시 지킬 방향
1. 구현 전 문서 승인 우선
2. renderer는 파일을 직접 읽지 않음
3. Excel 파싱, 매칭, 분석, 적용은 main service에서 처리
4. 적용 전 반드시 미리보기 제공
5. 저장은 기존 이력 구조를 최대한 재사용
6. 패턴 산출 결과는 즉시 저장하지 않고 Site 1단계 draft만 채움
7. 설명 가이드는 한국어, 단계형, 따라 하기 쉬운 구조 유지

## 3. 확정한 설계 결정

### 3.1 시급 일괄 업데이트
- 메뉴: `인력 관리`
- 진입: 상단 액션 버튼
- 식별 기준: `근무지명 + 이름`
- 저장 방식: 기존 `wage_rates` 이력 구조 재사용
- 적용 방식:
  - 기존 활성 시급 종료일 = 적용일 전날
  - 신규 시급 이력 추가
  - `reason`에 `시급 일괄 업데이트` + 원본 파일명 기록
- 적용 제외:
  - 근무지명 불일치
  - 이름 중복
  - 시급 파싱 실패
  - 빈 행
  - 적용일 오류
  - 동일 금액

### 3.2 패턴 산출 및 적용
- 메뉴: `근무지 관리`
- 진입: 분석 모달 -> `근무지 등록(1단계 이동)`
- 외부 문서 기준 범위:
  - 엑셀 파싱
  - 패턴 탐지
  - 그룹 분류
- 앱 변환 규칙:
  - 그룹 1개 = Cycle 1개
  - `같은 그룹 + 같은 offset` = 조 1개
  - 해당 인원 수 = 조 정원
- 적용 방식:
  - DB 즉시 저장 금지
  - Site 1단계 draft 자동 주입
  - 근무시간 / 휴게시간은 기본값 채운 뒤 사용자 검토

## 7. 구현 중 방향 이탈 방지 체크
- 지금 만드는 기능이 `파일 선택 -> 가이드 -> 미리보기 -> 적용` 흐름을 따르는가?
- 계산 / 파싱 로직이 renderer에 새로 들어가고 있지 않은가?
- 시급 저장이 새 테이블이 아니라 기존 이력 구조로 처리되는가?
- 패턴 산출 결과가 DB 저장이 아니라 draft 주입으로 끝나는가?
- 적용 제외 사유를 사용자가 읽을 수 있게 노출했는가?
- 가이드가 텍스트 벽이 아니라 예시 표 / 도식 중심인가?

## 8. 현재 미결정 항목
1. 시급 일괄 적용에서 `근무지명 + 이름` 외 보조 키가 필요한지 여부
2. 패턴 산출 시 조 라벨 생성 방식을 `A조, B조...`로 고정할지 여부
3. 패턴 산출 결과의 신뢰도 / 경고 노출 수준
4. 가이드 도식을 inline SVG로 할지, 표 기반 컴포넌트로 할지 여부
