## 시나리오 1. 최초 운영 세팅과 양식 기준 확정

### 목적
- 빈 DB에서 운영 기본값을 다시 세팅하고, 새 양식 관리 편집기가 실제 운영 준비 단계에서 문제없이 동작하는지 확인한다.

### 준비
- 앱 실행 후 로그인
- 운영 관리 접근 권한이 있는 계정 사용
- 사용할 양식 원본 파일 준비
  - 근무표
  - 품의서
  - 별첨1
  - 별첨2

### 실행 순서
1. 운영 관리에서 경로 설정을 저장한다.
2. 사용자 관리에서 기본 운영 계정을 확인하거나 필요한 계정을 추가한다.
3. 요율 관리에서 당해 연도 요율 버전을 신규 등록한다.
4. 양식 관리에서 각 문서 종류를 하나씩 등록한다.
5. 구조 확인 결과가 정상적으로 보이는지 확인한다.
6. 도식 미리보기에서 제목, 표, 결재 영역을 클릭해 속성 패널 대상이 정확히 바뀌는지 확인한다.
7. 대표 위치, 열 너비, 행 높이, 배경색, 정렬, 병합을 일부 조정한다.
8. 검증 출력 후 저장한다.
9. 저장된 버전을 승인하고 기본 사용으로 전환한다.
10. 양식 변경 이력에 등록, 수정, 승인, 기본 사용 기록이 남는지 확인한다.

### 기대 결과
- 경로 설정과 요율 기준이 정상 저장된다.
- 양식 관리 편집기에서 클릭한 영역과 속성 패널 대상이 정확히 일치한다.
- 검증 출력 결과와 도식 미리보기의 큰 구조가 어긋나지 않는다.
- 승인된 기본 사용 버전이 이후 출력 기준으로 선택 가능 상태가 된다.

## 시나리오 2. 실적 승인부터 수당 계산과 품의 승인 마감까지

### 목적
- 실제 운영 핵심 흐름인 실적 승인, 수당 산출, 문서 출력, 품의 승인, 자동 백업이 한 번에 이어지는지 검증한다.

### 준비
- 승인대기 폴더에 테스트용 실적 파일 준비
- 운영 관리에서 경로와 양식 기본 사용 기준이 이미 확정돼 있어야 함
- 요율 관리에서 적용 중 요율 버전이 존재해야 함

### 실행 순서
1. 실적 파일을 승인대기 폴더에 넣고 실적 관리에서 파일이 인식되는지 확인한다.
2. 실적 비교/승인 모달에서 승인과 반려를 적절히 처리한다.
3. 승인완료 보관본이 생성되는지 확인한다.
4. 수당 관리에서 승인된 실적 기준으로 산출 결과가 생성되는지 확인한다.
5. 수당 승인으로 상태를 `승인`으로 정리한다.
6. 품의 승인 미리보기에서 포함 대상, 일반 지급, 선지급, 합계를 검토한다.
7. PDF와 Excel 문서를 출력한다.
8. 최종 품의 승인 버튼으로 마감한다.
9. 내부 모달 완료 메시지, 자동 백업, 품의 승인 기록, 활동 이력까지 확인한다.

### 기대 결과
- 상태 흐름이 `검토대기 -> 승인 -> 품의승인`으로 자연스럽게 이어진다.
- 품의서, 별첨1, 별첨2가 현재 기본 사용 양식 기준으로 정상 출력된다.
- 품의 승인 이후 자동 백업과 승인 기록이 함께 남는다.
- 활동 이력에서 문서 출력과 품의 승인 행위를 다시 추적할 수 있다.

## 시나리오 3. 반려, 재승인, 요율 변경, 감사 추적 검증

### 목적
- 예외 상황에서 데이터 무결성과 감사성이 유지되는지 확인한다.

### 준비
- 실적 승인과 수당 산출이 한 번 끝난 테스트 데이터 준비
- 요율 수정 권한이 있는 운영 계정 사용

### 실행 순서
1. 수당 관리에서 `근무지 반려`를 실행하고 반려 사유를 입력한다.
2. 실적 관리에서 해당 파일이 pending으로 복귀했는지 확인한다.
3. 재승인 대상 행을 다시 승인하고 파일 확정이 가능한지 확인한다.
4. 수당 관리에서 다시 산출을 생성하고 승인 상태로 정리한다.
5. 운영 관리 요율 관리에서 기존 적용 중 요율을 수정한다.
6. 수정 시 `변경 사유`가 필수인지 확인한다.
7. 수정 시 적용 시작일을 오늘 이전 날짜로 바꾸려고 할 때 차단되는지 확인한다.
8. 활동 이력에서 근무지 반려, 재승인, 요율 변경 사유가 모두 남는지 확인한다.

### 기대 결과
- 근무지 반려 사유 없이 되돌리기가 진행되지 않는다.
- 재승인 완료 전에는 파일 확정이 되지 않는다.
- 이미 시작된 요율 기준의 소급 변경이 차단된다.
- 활동 이력과 변경 이력에서 반려, 재승인, 요율 변경 사유를 다시 읽을 수 있다.

## 테스트 마감 체크
- 각 시나리오 종료 후 결과 화면 캡처를 남긴다.
- 실패 시 어느 단계에서 어떤 기대 결과가 깨졌는지 단계 번호 기준으로 기록한다.
- 양식 문제인지, 상태 흐름 문제인지, 감사 이력 문제인지로 분류해서 후속 수정 범위를 정한다.
